# Модуль data-erasure

**Створено:** 2026-11-13 · **Оновлено:** 2026-11-13

Картка модуля (ARC-01). Робота з модулем починається з неї; оновлюйте її в тому ж PR, що й інтерфейс.

## Призначення

Видалення акаунта і всіх його даних на запит людини через власника продукту (NFR-12@PoC п. 3), повторне застосування
видалень після відновлення з копії (NFR-16@PoC п. 9). Закриття акаунта людиною самостійно — з MVP (ARC-01).
Рішення — [ADR-0013](../../../../../docs/adr/0013-erasure-in-append-only-tables.md) (варіант A, рішення власника 2026-11-13).

## Вимоги

NFR-12@PoC п. 3 (запит, видалення протягом 30 днів, знищення ключа простору); NFR-16@PoC п. 9 (журнал запитів поза
основною базою, повторне застосування після відновлення).

## Публічний інтерфейс

`index.ts`:

- `createDataErasure({ databases, erasureDatabases, log, now? })` → `DataErasure`:
  - `request({ email } | { accountId })` → стан запиту — записує запит у журнал видалень (строк = +30 днів) і в журнал
    платформи (`data-erasure.request`, `dueAt`). Простір з іншим учасником — `SPACE_SHARED`, нічого не записано; повторний
    запит для того самого акаунта повертає наявний.
  - `run(requestId)` — простори беруться в момент виконання (записані в запиті плюс поточні простори акаунта); акаунт
    (identity), далі для кожного простору: журнал проводок (ledger), журнал аудиту простору (audit), останнім ключ разом
    із записом простору (household) і ще раз журнал аудиту простору (запис щоденної задачі ключів між кроками). Перед
    кожним видаленням — запис у журналі платформи (`ledger.journal`, `audit.log`, акаунт, ключ). Завершення з усіма
    просторами — у журнал видалень і журнал платформи. Ідемпотентний.
  - `reapply()` — після відновлення повторює кожен завершений запит; повертає кількість.
  - `status()` — кожен запит: стан, строк, днів лишилося, прострочення.
- `ErasureError` (`ACCOUNT_NOT_FOUND`, `SPACE_SHARED`, `REQUEST_NOT_FOUND`), `ERASURE_DEADLINE_DAYS`, тип `RequestState`.

Хто викликає: лише `apps/api/scripts/erasure.ts` — дозволена дія власника продукту в production (зі схваленням власника
на кожен запуск). `erasureDatabases` дає `withErasureDatabases` (`platform/db/erasure-db.ts`), `log` — `erasureLog`
(`platform/adapters/erasure-log`; робоча реалізація ще не збудована й відмовляє закрито).

## Залежності

Шар: process. Модулі: audit, household, identity, ledger (`apps/api/module-rules.json`) — лише їхні інтерфейси видалення.
Зовнішні сервіси: журнал видалень через порт `erasure-log`.
