# Модуль audit

**Створено:** 2026-11-06 · **Оновлено:** 2026-11-06

Картка модуля (ARC-01). Робота з модулем починається з неї; оновлюйте її в тому ж PR, що й інтерфейс.

## Призначення

Журнал аудиту лише на дописування: хто, коли (UTC), яку сутність, які поля, значення до і після, через
який канал змінив у просторі (П-10). Змінити або видалити запис неможливо.

## Вимоги

ARC-03@PoC (п. 5: журнал лише на дописування). Повні функції журналу (перегляд, фільтри, експорт) додадуть
вимоги ACC, які його використовують.

## Публічний інтерфейс

`index.ts`:

- `auditModule` — опис модуля.
- `createAuditLog(db)` → `AuditLog`, де `db` — `ModuleDatabases.for("audit")`:
  - `record(householdId, entry)` — дописує запис. `entry`: `actor` (`{ kind: "user" | "staff", id }` або
    `{ kind: "system" }`), `channel` (`web`, `api`, `import`, `system`), `entity` (`{ type, id }`, тип на кшталт
    `accounts.account`), `action` (`create`, `update`, `delete`), `changes` (`{ field, before, after,
sensitive }`). Значення полів з `sensitive: true` замінюються на `AUDIT_MASK` до запису; ідентифікатори —
    лише непрозорі UUID, без імен і email.
  - `entriesFor(householdId, entity)` — записи однієї сутності в хронологічному порядку.
- Типи `AuditEntry`, `AuditEntryInput`, `AuditChange`; константа `AUDIT_MASK`.

Запис іде окремою транзакцією модуля `audit`; атомарність зі зміною даних прийде з подіями (ARC-04).
