# «Старт» profile: staging and production

**Створено:** 2026-11-06 · **Оновлено:** 2026-11-06

CICD-07@PoC: the cloud infrastructure of the «Старт» deployment profile (ARC-08) as OpenTofu code, in
Oracle Cloud Infrastructure. One code base, two environments (CICD-04), each with its own state,
compartment, keys and buckets.

| What | Where | Rule |
| --- | --- | --- |
| Compartment per environment | `network.tf` | CICD-04: separate secrets, keys and domains |
| Network: VCN, public subnet; only TCP 80 and 443 come in; no SSH from the internet; the VCN's default security list is emptied | `network.tf` | CICD-08 FR2 |
| Server: one Ampere A1 VM (free tier), Ubuntu 24.04, Docker, automatic security updates; disk encrypted with the KMS key and preserved if the server is replaced; IMDS v2 only | `server.tf`, `cloud-init.yaml` | ARC «Старт», ARC-06, CICD-12 |
| OCI Vault with HSM keys: application master key, storage key | `kms.tf` | ARC-06 FR1, CICD-12 FR4, NFR-16 FR2 |
| Files bucket (private, KMS-encrypted, versions kept 35 days) | `storage.tf` | ARC-06 FR4 |
| Off-site copies and the secrets package in another EU region (private, kept exactly 35 days, no hidden versions, a retention rule forbids deleting or changing them earlier) | `storage.tf` | CICD-07 FR2, NFR-16, ARC-06 FR5 |
| Server identity (instance principal) and least-privilege policies: the server cannot delete copies | `access.tf` | CICD-12, NFR-16 |
| State in Object Storage, encrypted on the client (AES-GCM), enforced | `versions.tf` | CICD-12 |
| The vault, both keys, all buckets and the server have `prevent_destroy`: a plan can never delete them; removing one takes a deliberate code change first | `kms.tf`, `storage.tf`, `server.tf` | ARC-06 FR1, CICD-07 FR2 |

Regions: primary **eu-madrid-1** (NFR-17), copies **eu-frankfurt-1**. Losing the whole Madrid region (and with
it the master key) is an accepted risk for «Старт» (owner, 2026-11-06); the copies protect against the
loss of the server. Sizes per environment are in
`env/<environment>.tfvars`; together they stay inside the free tier (4 OCPU, 24 GB, 200 GB disk).
The copies in Frankfurt are outside the free tier (it covers Object Storage in the home region only)
and are billed by size: for PoC an estimated 10–40 GB, well under 1 EUR a month. The 5 EUR budget alarm
(`owner-setup.md`) covers it.

## Checks

Every PR runs the CI job `infra`: the static rules in `tools/infra-check` (`node --test tools/infra-check`),
`tofu fmt -check` and `tofu validate` with the pinned OpenTofu and OCI provider. No cloud access is used
there; nothing is planned or applied.

## Bootstrap (owner, once)

These steps need the owner's own cloud account and are never done by agents (CICD-12):

1. Create the OCI account: Pay As You Go, home region Madrid, Frankfurt subscribed, MFA and a budget
   alarm. Step by step: [owner-setup.md](owner-setup.md).
2. Create the state bucket `willowsum-tofu-state` (private, versioned) in Madrid and a customer secret
   key for the S3-compatible API, kept in the secrets store.
3. Put the state passphrase (≥ 32 random characters) in the secrets store, one per environment.
4. Set up the OIDC trust between GitHub and the cloud for the `main` branch (CICD-12), so the pipeline
   can plan and apply without stored keys.
