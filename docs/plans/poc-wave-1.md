Рядки 1–10 частини A злиті (PR #68, #73, #74, #75, #77, #80–#87). Далі:

   режим телеметрії `off` для production PoC (структуровані логи на сервері без експорту).

3. NFR-09 (рядок 11) і документи безпеки (рядок 19) — пізніше, паралельно з функціями. Рядок 19 у PoC — лише модель
   загроз на одну сторінку; решта (реєстр ризиків, SLA на вразливості як документ, реєстр обробки, процедура на
   випадок витоку) — у MVP.

PoC користується лише родина власника зі справжніми даними: захист даних і резервні копії лишаються повними;
спостережуваність PoC — структуровані логи на сервері і перевірка «живий» (запланований робочий процес GitHub Actions
перевіряє `/health/ready` кожні 5–10 хв і відкриває або оновлює issue, про яке GitHub пише власнику; будується разом
із розгортанням, CICD-07). Grafana Cloud, SLO, правила алертів і черговий — з MVP. Середовище одне — production;
staging — з MVP.

## Гілки

Кожен PR іде з робочої гілки, яку отримала ця сесія. Після злиття гілка перезапускається від свіжого `main`
під наступний PR. Назва PR починається з ID (CI це перевіряє). Рішення ведучого: так зберігаються
і правило «одна гілка на сесію», і `AGENTS.md` (ID у назві PR); див. журнал рішень.

   з DPA або розгорнути власний на OCI.
2. Перевірка скомпрометованих паролів (Have I Been Pwned, k-anonymity) для ACC-01 і NFR-01: провайдер отримує
   лише 5 символів хешу. Потрібне підтвердження, що це не обробник персональних даних.
3. Другий хранитель ключа відновлення секретів (NFR-15, п. 33).
4. Інфраструктура для production (хвилі 2–4: CICD-07, CICD-05, ARC-06; staging — з MVP, рішення 2026-11-12): OCI,
