# Рішення 2026-11-16: `pnpm local:dev` на Mac поруч з іншими інструментами (#363)

Малі рішення виконавця PR «CICD-04: local:dev on macOS»; власник їх не схвалював.

- Рішення ведучого (2026-11-16; власник не схвалював; #363 п. 4): новий запуск `pnpm local:dev` з тієї ж копії
  репозиторію зупиняє попередній запуск з `infra/local/.state/dev/pids.json`, навіть якщо той ще працює в іншому
  вікні: процес зупиняється, лише коли збігаються pid, час старту і командний рядок (`ps`), тож чужий процес із тим
  самим pid не зачіпається. Запуск з іншої копії репозиторію не зупиняється: людина бачить, хто тримає блокування
  кластера, і закриває його сама.
- Рішення ведучого (2026-11-16; власник не схвалював; #363 п. 1): нова змінна `WS_HOST` (`0.0.0.0` типово, як і
  раніше, або `127.0.0.1`) — `pnpm local:dev` запускає ролі на `127.0.0.1`; контейнер production не змінюється.
- Рішення ведучого (2026-11-16; власник не схвалював): `WS_LOCAL_DEV_DATABASE` (лише назва `ws_t_…`),
  `WS_LOCAL_DEV_STATE_DIR` і `WS_LOCAL_DEV_WEB_PORT` — лише для інтеграційного тесту скрипта, щоб він не чіпав `ws_dev`
  і порт 5173; людині вони не потрібні й у README не описані як її кроки.
- Рішення ведучого (2026-11-16; власник не схвалював): нові повідомлення скрипта — українською (порт 5173 зайнятий,
  хто тримає блокування, неготовність процесу, зупинка залишків); решта старих рядків лишилася англійською.
