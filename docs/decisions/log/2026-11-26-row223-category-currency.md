# Рішення 2026-11-26: валюта категорії — серверна частина (рядок 223)

**Створено:** 2026-11-26

Джерело: рішення власника 2026-11-26, Q3 а ([журнал](2026-11-26-owner-corrections.md)); BUD-02@PoC FR 1, FR 24, AC21,
бізнес-правила BUD-03@PoC і BUD-17@PoC. Нижче — дрібні рішення агента під час реалізації; власник їх не бачив.

- Рішення ведучого (2026-11-26; власник не схвалював; row 223): іншу валюту ліміту чи плану доходу сервер приймає лише
  тоді, коли для неї є курс на «сьогодні» простору; інакше — 400 `….currency: currency`, як і раніше для чужої валюти.
  Причина: FR 24 — «змінити на іншу валюту з курсом».
- Рішення ведучого (2026-11-26; власник не схвалював; row 223): рядок категорії в `GET /v1/budget/periods/{period}`
  віддає `limit`, `spent`, `remaining` (картка «Дохід» — `plan`, `actual`) у валюті категорії, а поле
  `inBudgetCurrency` — ті самі суми у валюті бюджету (null для категорії у валюті бюджету); `totals`, `summary` і
  «Можна витратити» складають суми у валюті бюджету. Поле `rates` (у бюджеті, періоді, «Можна витратити», «Плані»)
  називає курс і дату для «≈»; порожнє — без «≈». Курс подано як «1 одиниця валюти категорії = rate валюти бюджету»;
  зворотний вигляд підказки («1 € = 50,00 UAH») рахує клієнт (рядок 224).
- Рішення ведучого (2026-11-26; власник не схвалював; row 223): лінія поточного чи майбутнього періоду у валюті, для якої
  курсу немає зовсім, рахується в підсумках як 0 і названа в `rates` з `rate: null` — клієнт показує «Курс недоступний»,
  як для транзакцій без курсу. Для дня без власного курсу береться найближчий попередній, як усюди в бюджеті.
- Рішення ведучого (2026-11-26; власник не схвалював; #709): знімок завершеного періоду, коли для валюти лінії немає
  курсу на його останній день, зберігає власні суми ліній. Перше читання періоду після того, як курс цієї валюти
  з'явився, перераховує кожну таку лінію за найновішим курсом, відомим на момент цього читання (не за курсом
  найближчої дати після останнього дня), і записує цей курс у знімок назавжди; наступні читання його не змінюють.
  0 у знімку назавжди не лишається.
  Замінює попереднє рішення агента для знімків.
- Рішення ведучого (2026-11-26; власник не схвалював; row 223): клітинка категорії в «Плані» (BUD-17) — у валюті її
  поточного ліміту (без ліміту — у валюті бюджету); клітинка в іншій валюті — 400 `amount.currency: currency`. Клітинка,
  збережена в старій валюті після зміни валюти ліміту, лишається у своїй валюті й перераховується за курсом.
- Рішення ведучого (2026-11-26; власник не схвалював; row 223): перерахунок уже введеної суми при зміні валюти з
  округленням до 10 до парного (FR 24) робить поле на клієнті (рядок 224) — сервер зберігає суму так, як її надіслано.
  Збережений `budgets.income_plan` — сума планів доходу за курсом на день збереження; кожне читання перераховує
  за своїм курсом.
- Рішення ведучого (2026-11-26; власник не схвалював; row 223): зміна валюти ліміту чи плану доходу пише в аудит
  окреме поле `currency` (до і після); клітинка «Плану» — так само (#709: 3 000 UAH → 3 000 EUR — це зміна).
