# Рішення 2026-11-20: API «Можна витратити» (BUD-03@PoC c, перед рядком 126)

**Створено:** 2026-11-20 · **Оновлено:** 2026-11-20

Дрібні деталі, які BUD-03@PoC не задає, вирішено в PR «BUD-03: the «Можна витратити» read API (server part c)». Нових
рішень власника тут немає.

- Рішення ведучого (2026-11-20; власник не схвалював): окремий маршрут `GET /v1/budget/periods/{period}/spendable`, а не
  блок у `GET /v1/budget/periods/{period}`: картка і розбивка читають модулі goals і debt-payoff, яких сторінка періоду не
  потребує, і мають власний прапорець випуску `budget.spendable` (вимагає `budget.period`). Сума існує лише для поточного
  місяця (п. 1–4: «до кінця періоду», «з сьогодні»); інший місяць — 400 `period: not_current`; без бюджету — 404
  (AC7: картки немає, сторінка показує порожній стан з `GET /v1/budget`).
- Рішення ведучого (2026-11-20; власник не схвалював): джерело без суми (платіж чи дохід без жодного курсу, ціль без
  курсу, заплановані витрати без курсу, сума понад 15 цифр) — `figures: null` і список `unavailable`; картка показує
  «Не вдалося розрахувати суму», а не суму без нього (як «Розподіл» і рядок підсумку, #567).
- Рішення ведучого (2026-11-20; власник не схвалював): регулярні доходи, що ще очікуються (п. 3), — списання доходів
  місяця зі статусом «Очікується» або «Прострочено» з того самого читання recurring, що й регулярні платежі
  (`BudgetObligations.incomeExpected`), за сьогоднішнім курсом; від прапорця `budget.plan` не залежать. Без курсу — лише
  ця сума null, решта чисел місяця (рядок підсумку, «Очікувані платежі») лишається.
- Рішення ведучого (2026-11-20; власник не схвалював): «уже внесене в цьому місяці» (п. 6) — те саме число, що «цього
  місяця» на картці цілі (`GoalPlans.contributedThisMonth`): внески за місяць, для цілі на власному рахунку — приріст
  залишку рахунку з 1-го числа (не менше 0), за сьогоднішнім курсом. Заплановані заощадження для бюджету без лімітів
  (п. 10) — заплановані внески всіх активних цілей і «Заощадження без цілі» місяця з «Плану», до віднімання внесеного.
- Рішення ведучого (2026-11-20; власник не схвалював): API повертає основу відтінку перевитрати (`overspend.base` —
  ліміти необов'язкових категорій), а рівень `over-1`…`over-8` рахує спільне правило `overLevel` пакета `packages/ui`
  (DS-23 п. 4), як для рядка підсумку періоду. Назви регулярних платежів, цілей і рахунків розбивка не дублює: вона
  повертає ідентифікатори джерел (`paymentId`, `goalId`, `accountId`, `categoryId`) для переходу до кожного (п. 8), назви
  сторінка бере з їхніх модулів.
- Рішення ведучого (2026-11-20; власник не схвалював): дату щомісячного платежу кредиту (п. 5: день останнього платежу
  або 1-ше число) розбивка поки не показує — порт `AccountPayments` дає лише факт оплати в місяці; це follow-up.
