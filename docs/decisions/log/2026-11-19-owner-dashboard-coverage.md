# Рішення власника 2026-11-19: сторінка ходу PoC показує покриття вимог PoC тестами

**Створено:** 2026-11-19 · **Оновлено:** 2026-11-19

- Рішення власника (2026-11-19, чат): на пропозицію ведучого відповідь «так» — обрано варіант а.
- Варіанти, як їх запропонував ведучий:
  - «а) головне число стає покриттям PoC, лічильник PR лишається поруч як темп, CI пише числа після кожного злиття в main»;
  - «б) лишити як є, з підписом «PR за планом, не готовність»».
- Ведучий рекомендував а. Відповідь власника: «так».

## Чому

Головне число сторінки https://minakovval.github.io/Willowsum/ (77 %) — це кількість злитих PR без префікса
`PRC-` з 2026-11-13, поділена на оцінку плану хвилі 2 (≈ 262). Воно завищує хід: виправлення, прибирання й зміни
вимог теж рахуються як прогрес, оцінка росте, і число стосується лише PoC. Чесна міра — покриття вимог PoC тестами з
`node tools/req-check/index.mjs --coverage` (близько 52 % на цей день): частка пунктів FR, AC і EC, названих тестами.

## Що змінено

- Джерело сторінки перенесено в main: `tools/progress-dashboard/index.html` (зміни проходять рев'ю).
- `node tools/req-check/index.mjs --coverage-json <file> --sha <commit>` пише покриття по релізах (FR, AC, EC
  covered/total, час і коміт main).
- `.github/workflows/progress-dashboard.yml` після кожного push у main рахує JSON і публікує `index.html` та
  `coverage.json` у гілку `gh-pages`; токен на запис — лише в job `publish`, який не запускає код репозиторію.
- Сторінка: головне — «Вимоги PoC покриті тестами» (%, кількості, FR/AC/EC), PoC v2 і MVP менше; лічильник злитих
  PR і графік — у блоці «Темп»; дата й коміт покриття; без `coverage.json` — «немає даних»; запасне число 251 і
  прогноз дати за оцінкою PR прибрано.

## Ризики, мінуси, пом'якшення (`references/lead-communication.md` п. 5)

- Мінус: покриття рахує пункти, названі хоча б одним тестом, а не якість тестів; 100 % не означає готовий PoC.
- Ризик: workflow з правом запису в репозиторій. Пом'якшення: `contents: write` лише в job, що копіює два файли в
  `gh-pages`; код репозиторію виконується в окремому job лише з читанням; дії закріплені за SHA; без секретів.
