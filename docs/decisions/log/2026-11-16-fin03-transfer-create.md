# Рішення 2026-11-16: переказ між рахунками однією дією — серверний запит

Малі рішення виконавця PR «FIN-03: transfer between accounts in one action (FR 1, FR 28) — server» (#437). FIN-03@PoC
FR 1 і FR 28 називають тип «Переказ між рахунками» форми «Нова транзакція», але не описують його поля і запит, а дошка
`PocMoneyNewTx` показує лише тип у перемикачі.

- Рішення ведучого (2026-11-16; власник не схвалював): запит `POST /v1/transactions/transfers` (`createTransfer`) за
  прапорцем і ключем `transactions.transfers` (як «Позначити як переказ»), з `Idempotency-Key` (ARC-07 FR 4). Поля:
  `fromAccountId`, `toAccountId`, `amount` (додатна, у валюті рахунку списання — «Сума», FR 28), необов'язкова
  `received` (додатна, у валюті рахунку зарахування), `date`, `counterparty`, `description` (на обох сторонах).
  Відповідь 201 — `{ outflow, inflow }`. Поля «Статус» немає: сторона переказу завжди «Проведена», як у «Позначити як
  переказ».
  Схвалено власником 2026-11-17 (2026-11-17-owner-batch.md): переказ, внесений вручну, не має статусу «Очікує».
- Рішення ведучого (2026-11-16; власник не схвалював): без `received` в одній валюті зараховується сама сума; у двох
  валютах — сума за офіційним курсом дати (або найближчим попереднім, як у fx-rates; VAL-04 FR 4), округлена до парного
  до мінімальних одиниць валюти зарахування (рішення власника 2026-11-16, #419: до парного в обчисленнях і зберіганні).
  `received` в одній валюті не більша за `amount`: різниця — комісія (FR 8), як у «Позначити як переказ».
- Рішення ведучого (2026-11-16; власник не схвалював): рахунок іншого простору чи невідомий, з будь-якого боку, — 404
  «не знайдено» (П-5, FIN-03 AC11), тоді як `createTransaction` відповідає на невідомий рахунок 400 `accountId: not_found`.
  Немає курсу дати у двох валютах — 400 `date: rate_unavailable`. Мультивалютний рахунок зарахування без `received` —
  субрахунок валюти списання, якщо він є, інакше перший субрахунок.
- «Сьогодні» для поля «Дата» — та сама перевірка, що в `createTransaction` (поки київська дата): функції платформи
  `today(space)` (П-27) у `main` ще немає (план хвилі 2, рядки 176–179); перехід зробить той рядок для обох запитів.
- Рішення ведучого (2026-11-17; власник не схвалював; #456): порядок перевірок FIN-03 — спершу поля, потім закритий рахунок; закритий `from` з помилками полів дає 400, як `to` і createTransaction.
