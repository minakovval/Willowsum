# Рішення ведучого 2026-11-18: BUD-05@PoC d) — «Витратити з цілі» (S-139)

**Створено:** 2026-11-18

- Рішення ведучого (2026-11-18; власник не схвалював; #555): BUD-05@PoC FR 8 — рядок «у цілі залишиться …» і сума обраних транзакцій у діалозі «Витратити» рахуються на клієнті як одновалютні `Money` (сума обраних, різниця до «Зібрано»); бо API не має запиту попереднього розрахунку списання, а дошка PocPlanGoalSpend показує цей рядок ще до підтвердження. Після підтвердження картка показує `collected` з відповіді API. Подальша дія: попередній розрахунок на сервері, якщо власник цього захоче.
- Рішення ведучого (2026-11-18; власник не схвалював; #555): BUD-05@PoC FR 8, FR 9 — перемикач «Закрити ціль» кроку 2 виконує після успішного списання окремий виклик `POST /v1/goals/{id}/close`; бо спільного ендпоінта «списати і закрити» немає. Якщо закриття не вдалося, витрата лишається записаною, діалог каже про це.
- Рішення ведучого (2026-11-18; власник не схвалював; #555): BUD-05@PoC FR 8 — діалог читає до 100 транзакцій однією відповіддю `GET /v1/transactions` (фільтри `type.eq:out`, `transfer.eq:false`, `hidden.eq:false`, `status.eq:posted`, рахунок частини) і показує по 6; бо найменша сторінка списку — 25 рядків, а API ще не відсіює вже списані транзакції (вони вилучаються за `goal.spends`).
