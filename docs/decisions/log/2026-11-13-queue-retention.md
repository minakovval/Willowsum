# Рішення 2026-11-13: ARC-11 — подія «проводку записано», вільний текст у ledger, строки черги

**Створено:** 2026-11-13 · **Оновлено:** 2026-11-13

Дрібні технічні рішення виконавця PR «ARC-11: ledger entry-recorded event via the outbox, no free text in the ledger
schema» (гілка `claude/gracious-feynman-k4ne4r-arc11-outbox`; issues #125, #128 і подальші кроки PR #174). Питання
власнику — у тілі PR.

- Рішення ведучого (2026-11-13; власник не схвалював; цей PR): подія `ledger.entry-recorded` v1 має лише
  ідентифікатори, коди й дати (`entryId`, `sourceModule`, `sourceId`, `eventType`, `operationDate`, `recordedAt`,
  `reversesEntryId`); схема сувора (`z.strictObject`), а CHECK таблиці `ledger.outbox_events` відхиляє будь-який
  рядок у даних, що не є кодом. Пишеться для кожного нового запису (`post`, `reverse`, `correct`), не для повтору ключа.
- Рішення ведучого (2026-11-13; власник не схвалював; цей PR): правило «у таблицях ledger немає вільного тексту» —
  у `schema-rules.ts` (`LEDGER_CODE_COLUMNS`): текстова, JSON-, бінарна колонка чи масив у схемі `ledger` дозволена,
  лише якщо вона в списку і має власний CHECK «лише код» (шаблон, перелік значень чи jsonpath `like_regex`). Для цього
  ключ ідемпотентності записів став кодом `^[A-Za-z0-9:._-]{1,200}$` (ARC-11: ключ — ідентифікатор події джерела),
  а `postings.currency` отримав власний CHECK (міграція `0005_ledger_codes.sql` — крок «contract» ARC-03 п. 4: поза
  тестами ledger ще ніхто не викликає).
- Рішення ведучого (2026-11-13; власник не схвалював; цей PR): строки зберігання рядків черги — відправлені події й
  виконані задачі 7 днів, задачі в черзі невдалих 30 днів (`QUEUE_RETENTION_DAYS`); невідправлені події й задачі в
  черзі чи в роботі не видаляються. Це робочі копії: зміна, про яку вони повідомляють, лишається в таблицях модуля,
  тож це не категорія даних простору з таблиці строків NFR-12. Прибирання — щоденна задача планувальника
  `queue.retention-cleanup`; без запису аудиту (дані простору не змінюються), без нових атрибутів телеметрії.
- Рішення ведучого (2026-11-13; власник не схвалював; цей PR): воркер уже обслуговує чергу `ledger`, хоча споживачів
  «проводку записано» ще немає: події позначаються відправленими і через 7 днів видаляються. Проєкції, що з'являться
  пізніше, будують початковий стан із журналу (ARC-11: журнал — єдине джерело правди).
- Рішення ведучого (2026-11-13; власник не схвалював; цей PR): пул з'єднань модуля в ролі воркера —
  `DEFAULT_CONCURRENCY + 1` (`wiring.ts` `modulePoolSize`), інші ролі — типові 3 (рев'ю #174, N1).
