#736 (NFR-01, ротація ключів даних) зайняв ≈ 7 год: дві справжні знахідки про втрату даних, 4 очікування CI і 6

## Рішення

- Рішення власника (2026-11-27, чат): поки відкритий PR із позначкою `sensitive`, у якого триває security review або
  раунд виправлень, не зливати поперед нього PR, що змінює будь-який з його файлів (списки файлів двох PR
  перетинаються); той PR зливається після нього, якщо тільки він не виправляє червоний `main` чи проблему безпеки
  або власник не скаже інакше. Пропозиція ведучого, відповідь власника, дослівно: «так, запиши».
- Де записано: `.claude/skills/pr-pipeline/references/merge-checklist.md`, абзац «Order» (єдине місце). Щоб не
  збільшувати правила ведучого (1 088 рядків при ліміті 1 060, `.claude/references/process-limits.md`), стиснуто
  абзаци того ж файлу без втрати змісту: правила стало на 0 рядків більше, ніж було (1 088 → 1 088).
