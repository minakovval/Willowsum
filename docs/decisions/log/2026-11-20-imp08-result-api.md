# Рішення 2026-11-20: серверна частина кроку «Результат» (IMP-08, рядок 138)

**Створено:** 2026-11-20

Дрібні деталі, які вирішив автор PR «IMP-08: result API for the step «Результат»» (AGENTS.md «Ambiguity»: подання й межі
модулів, не продукт). Власник їх не схвалював; ведучий повідомляє його після злиття.

- Рішення ведучого (2026-11-20; власник не схвалював): крок «Результат» читає `GET /v1/import/batches/{batchId}/result` —
  збережені лічильники застосування (ті самі, що у відповіді «Застосувати») і `followUp`, обчислений під час читання, як
  простір є зараз (пари й категорії змінюються після застосування; крок можна відкрити знову, IMP-08 п. 1). Відповідь
  «Застосувати» не змінено. Кожне число дає модуль-власник через публічний інтерфейс: transactions (транзакції партії),
  categorization (чи є категорія), transfer-matching (пропозиції).
- Рішення ведучого (2026-11-20; власник не схвалював): «без категорії» (IMP-08 п. 11, AC7) — показані транзакції партії, не
  розділені (категорії мають частини) і не сторона переказу (категорія «Переказ»), без категорії в categorization.
- Рішення ведучого (2026-11-20; власник не схвалював): «пари переказів» партії — пропозиції «Пари · N» (те саме читання, що
  `GET /v1/transfer-proposals`, до 500 пар простору) хоча б з однією стороною, записаною цією партією; `more` — читання
  обмежене, як у маршруту пропозицій.
- Рішення ведучого (2026-11-20; власник не схвалював): «платежі на картку, записані як переказ» (IMP-08 п. 11, IMP-03 п. 15)
  — поле `cardPaymentTransfers`, поки завжди 0: застосування ще не записує платіж на картку з відомим власним джерелом як
  переказ (IMP-03 п. 15 — доробка). Так само, як `bankStatus` у рядках перевірки.
- Рішення ведучого (2026-11-20; власник не схвалював): «рядок відхилено» на крок «Результат» не потрапляє: у PoC
  застосування «все або нічого» — IMP-05@PoC п. 11 відхиляє застосування, доки не прийнято всі рішення, а рядок, який не
  можна записати, повертає 422 `IMPORT_ROWS_REFUSED` з номерами рядків; IMP-08@PoC п. 11 називає лише створені, замінені й
  пропущені рядки. «Відхилено» в лічильниках кроку перевірки (п. 5, AC3) — уже в `GET …/review` (рішення 2026-11-20
  `imp08-review-api`). Файл помилок (IMP-01@PoC п. 9, запис в історії імпорту) — не частина цього кроку.
- Рішення ведучого (2026-11-20; власник не схвалював; #673): відкочена партія (`rolled-back`, IMP-04 п. 8, IMP-16) на кроці
  «Результат» — партія зі своїм станом «відкочено», запис застосування (`result`, `appliedAt`) і `followUp: null`: її
  транзакції відкочено, нічого не лишилося, і старі лічильники не подаються як поточні; модулі не опитуються. Найменша
  зміна контракту — `followUp` може бути null. Застосування «в процесі» — 409 `BATCH_STATE_CONFLICT`, як і незастосована.
