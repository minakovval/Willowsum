## Що змінено

- `node tools/req-check/index.mjs --coverage-json` додає поле `version: 2` і список `features` для PoC: ID, назва, розділ, FR/AC/EC покрито/усього, кількість помилок відбитків, статус «готово» (усе названо тестами, 0 помилок відбитків), «у роботі» (щось названо), «не почато» (нічого). Вимоги поза PoC не перелічено. Наявні підсумки (`schema: 1`, `releases`) без змін.
- `tools/progress-dashboard/blocks.json` — єдиний файл відповідності ID → блок; `tools/req-check/test/blocks.test.mjs` падає, якщо вимога PoC не віднесена до блоку, віднесена двічі або вже не належить до PoC. CI кладе блоки в `coverage.json` (поля `blocks` і `block` у функції).
- Сторінка: блок «Готовність функцій PoC» — рядок блоку з рискою покриття FR/AC/EC, числом готових функцій і статусом (готово / у роботі / не почато), розгортається до згорнутого списку функцій (ID, назва, %, статус, посилання на відкритий PR). Відкритий PR із назвою «ID: …» піднімає «не почато» до «у роботі»; це робить сторінка в браузері за GitHub API, який вона вже викликає.
- `docs/plans/progress.json` позначено архівом: його не читає ні сторінка, ні інструмент.
- Workflow `progress-dashboard.yml`, права й розподіл на два job не змінено.

## Ризики, мінуси

- Готовність = пункти, названі тестами, а не якість тестів (як і в рішенні 2026-11-19).
