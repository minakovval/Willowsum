# IMP-07 a: шаблони простору (рядок 49)

**Створено:** 2026-11-26 · **Оновлено:** 2026-11-26

Дрібні рішення реалізації IMP-07@PoC (хвиля 2, рядок 49, серверна частина: шаблони в модулі `import-recipes`, автопідбір
на кроці розбору `import-sessions`). Попередні рішення про рецепти — [2026-11-19-imp06a2-recipe-storage.md](2026-11-19-imp06a2-recipe-storage.md).

- Рішення ведучого (2026-11-26; власник не схвалював; row 49): збережений рецепт і є шаблоном — окремого ресурсу немає,
  маршрути `/v1/import/recipes` розширено (`PUT`, версії, відновлення), поля відповіді лише додано (ARC-07 п. 3).
- Рішення ведучого (2026-11-26; власник не схвалював; row 49): стеля 200 рецептів (рішення 2026-11-19) замінена числом
  IMP-07 п. 2 — 100 шаблонів у просторі, той самий 422 `LIMIT_REACHED` з `limit`, не 402.
- Рішення ведучого (2026-11-26; власник не схвалював; row 49): область задає `accountId` (є — «рахунок», немає — «простір»),
  без окремої колонки області, тож міграція лише розширює таблицю. Рахунок перевіряє порт `accounts.postingAccount`
  (з'єднання в `src/main.ts`, модуль від accounts не залежить): чужий чи невідомий — 404, закритий — 409 `ACCOUNT_CLOSED`.
- Рішення ведучого (2026-11-26; власник не схвалював; row 49): назва унікальна в межах області й рахунку без урахування
  регістру; перевіряє модуль під замком збережень простору, не унікальний індекс (його не витримав би попередній код під
  час розгортання, ARC-03 п. 4). Конфлікт — 409 `TEMPLATE_NAME_TAKEN`.
- Рішення ведучого (2026-11-26; власник не схвалював; row 49): «Шаблон змінено, оновіть» — 409 `TEMPLATE_CHANGED` з
  `currentVersion`; збереження й відновлення вимагають `expectedVersion`. Відновлення бере з версії рецепт, запечатане
  значення прив'язки й відбиток; назва й область лишаються поточними (щоб відновлення не впиралось в унікальність назви).
- Рішення ведучого (2026-11-26; власник не схвалював; row 49): редактор бачить значення прив'язки лише замаскованим, тому
  збереження рецепта з тим самим способом прив'язки (`iban`, `account-number`, `mask`) без значення зберігає запечатане.
- Рішення ведучого (2026-11-26; власник не схвалював; row 49): «застарілий» — версія схеми рецепта нижча за поточну; такий
  шаблон не підбирається, а обраний вручну для розбору — 409 `TEMPLATE_STALE`. Лічильник використань рахує крок розбору
  після збереженого розбору, один раз на розбір (`last_used_parse`); у записі аудиту відновлення — дія `update` з полем
  `restoredVersion` (журнал знає лише `create`, `update`, `delete`).
- Рішення ведучого (2026-11-26; власник не схвалював; row 49): типізований рецепт у контракті — у відповіді схема модуля
  (`recipeSchema`, переліки `x-extensible-enum`, `schemaVersion` — ціле ≥ 1, без `account.value`); у запиті рецепт і далі
  перевіряє модуль (422 з кодами й шляхами), а контракт описує його як `anyOf` — рецепт, JSON-текст або будь-яке інше
  значення (відхиляється 422), бо звуження типу запиту несумісне з базовим контрактом.
