# Рішення 2026-11-20: API «Підсумок періоду» (FLW-38@PoC, S-135, рядок 149 хвилі 2)

**Створено:** 2026-11-20 · **Оновлено:** 2026-11-20

Дрібні деталі, які FLW-38@PoC і BUD-02@PoC п. 16 не задають, вирішено в PR «FLW-38: «Підсумок періоду» API (server
part)». Нових рішень власника тут немає.

- Рішення ведучого (2026-11-20; власник не схвалював): маршрут `GET /v1/budget/periods/{period}/summary` — у модулі
  `budget`, а не `reports`. «Підсумок періоду» — вигляд минулого місяця сторінки «Бюджет» (BUD-02 п. 16), його числа —
  план зі знімка і факт періоду, які рахує лише `budget`; модуль `reports` (звіти і конструктор звітів, каталог ARC-01 —
  MVP) лишається каркасом. FLW-38 називає обидва модулі («Модуль: budget, reports»), тож текст вимоги не змінено. Власний
  прапорець випуску `budget.summary` (вимагає `budget.period`).
- Рішення ведучого (2026-11-20; власник не схвалював): «Витрати» картки — усі витрати рахунків бюджету: категорії з
  лімітом і «Поза планом» (з «Без категорії»); план — сума лімітів зі знімка. Чистий потік і норма заощаджень — з цих
  самих доходу й витрат (FLW-38 п. 1), відсоток з одним знаком до парного, як у «Грошовому потоці» (BUD-08); без доходу —
  null («–», EC1).
- Рішення ведучого (2026-11-20; власник не схвалював): картка «Регулярні платежі» завершеного місяця — списання
  витратних регулярних платежів (регулярні доходи — у картці «Дохід», BUD-02 п. 3), хоч який стан платежу зараз:
  «Можливо, скасований» чи завершений пізніше лишають свої списання того місяця (історія — факт). «сплачено N з M» —
  `paid` (вчасно і із запізненням) з `count`; «K із запізненням» — `late`; дата оплати — `paidOn` («Сплачено із
  запізненням · 12 лист.»). Назви платежів сторінка бере з `GET /v1/recurring/payments`.
- Рішення ведучого (2026-11-20; власник не схвалював): три найбільші зміни («ПОРІВНЯНО З СЕРЕДНІМ ЗА 3 МІС.») і таблиця
  категорій — наявні `GET /v1/budget/compare?type=month&period=…&base=avg3` (`largest`, `base.window`) і
  `GET /v1/budget/periods/{period}`; новий маршрут їх не дублює.
