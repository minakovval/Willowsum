# Рішення 2026-11-16: ключ прапорця `data.bulk_actions` — розширити правило ключа в БД, а не перейменовувати

Рішення ведучого (2026-11-16; власник не схвалював): прапорець `data.bulk_actions` (DAT-03@PoC a) не можна було
зберегти — CHECK `feature_flags.flags.key` дозволяв у частинах лише `[a-z0-9-]`, тож `/v1/bulk-actions` не вмикався
ні вручну, ні через `node scripts/flags.ts rollout`. Виправлено новою міграцією модуля feature-flags
(`0002_flag_key_underscore.sql`): частини ключа можуть містити й «_». Ключ функції не перейменовано, бо:

- ключ `data.bulk_actions` записаний у тексті вимоги (DAT-03, «Ліміти», PoC / MVP / v1) і в UC-DAT; перейменування —
  зміна вимоги, яка потребує рішення власника (AGENTS.md, PRC-02), а правило БД — деталь реалізації, вимоги його не задають;
- у вимогах наступних релізів є інші ключі з «_» (`vault.emergency_access`, `reports.builder_saved`,
  `assets.custom_fields`), тож перейменування лише цього ключа лишило б ту саму пастку.

Щоб це не повторилося: `pnpm check:flags` (CI) падає для ключа, який таблиця не прийме (`FLAG_KEY_PATTERN`), а
інтеграційний тест зберігає кожен ключ `FLAGS` на етапах «test», «share», «all» і звіряє `FLAG_KEY_PATTERN` з CHECK
таблиці на наборі ключів. Якщо власник захоче єдиний стиль ключів (лише «-»), це окрема зміна вимог (`change-requirement`).
