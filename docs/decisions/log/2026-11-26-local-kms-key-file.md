# Локальний адаптер KMS: випадковий ключ інсталяції (NFR-01@PoC п. 3, NFR-15@PoC п. 26)

**Створено:** 2026-11-26

Привід: безпековий огляд PR #722 (pullrequestreview-6079271447): єдиний локальний адаптер KMS виводив головний ключ із
фіксованої мітки у відкритому коді, тож копія локальної бази разом із репозиторієм розгортала кожен ключ простору. Текст
вимог — у #722 (ще не злитий); цей PR будує за ним.

Рішення ведучого (2026-11-26; власник не схвалював; local KMS): дрібні деталі, вирішені в PR.

- **Позначка реальних даних — `WS_REAL_DATA=true`.** Екземпляр із цією позначкою (так запускає `pnpm local:dev`, база
  `ws_dev` власника) не стартує без файлу ключа `WS_KMS_KEY_FILE` (помилка конфігурації називає змінну) і ніколи не
  отримує ключ фіксованої мітки. Без позначки (тести, CI, e2e) лишається ключ фіксованої мітки, версії `local-N`.
- **Файл ключа.** JSON з версіями `inst-N` (по 32 випадкові байти з CSPRNG), поточною версією і списком виведених із
  вжитку; створюється при першому запуску (папка 0700, файл 0600, атомарно, `O_EXCL`). Процес не стартує, якщо файл
  можуть читати чи писати інші користувачі (будь-який біт групи чи інших), він чужого користувача ОС, символьне
  посилання, лежить у цьому репозиторії чи будь-якому git-дереві (є `.git` у предках), папку можуть писати інші, або
  це не файл ключа. Змінна дає лише шлях; ключ зі змінної не читається ніколи. Помилки називають шлях і причину, не вміст.
- **Розташування за замовчуванням** — `~/.config/willowsum/local-kms-key.json`: поза репозиторієм, базою і папкою копій
  `~/Willowsum-backups`. `pnpm local:backup` відмовляється писати копію в папку файлу ключа і після кожної копії
  нагадує, що ключа в копії немає і його копію треба тримати окремо (менеджер паролів, інший диск).
- **Ротація і виведення з вжитку** — як у тестовому адаптері (`rotate`, `retire`), але записуються у файл одразу, тож
  їх бачать усі процеси інсталяції (файл перечитується, коли змінився). Команди ротації для власника в цьому PR немає
  (follow-up).
- **Разове переобгортання** — `scripts/kms-rewrap.ts [--dry-run]` (`pnpm --filter @willowsum/api kms:rewrap`): кожен ключ
  простору з версією `local-N` розгортається ключем фіксованої мітки і обгортається ключем інсталяції, з перевіркою і
  записом у журналі простору, як щоденне переобгортання. Ідемпотентне, сухий прогін лише рахує, звіт — лише лічильники.
  `pnpm local:dev` запускає його сам перед стартом процесів: інакше база власника після оновлення не відкрила б жодного
  зашифрованого поля. Ключ фіксованої мітки при цьому не губиться (він виводиться з коду), тож ризику втрати даних немає.
- **Розгорнуті середовища** (staging, production) файлу ключа не приймають (помилка конфігурації): там лише живий KMS (з MVP).
