# Рішення 2026-11-13: ARC-11 — кеш залишків за днями

**Створено:** 2026-11-13 · **Оновлено:** 2026-11-13

Дрібні технічні рішення виконавця PR «ARC-11: daily balance cache with version check and rebuild command» (гілка
`claude/gracious-feynman-k4ne4r-arc11-cache`; issue #126; хвиля 2, рядок 4). Питань власнику немає.

- Рішення ведучого (2026-11-13; власник не схвалював; цей PR): кеш — дві похідні таблиці схеми `ledger`:
  `daily_balances` (на рахунок і день із проводками — накопичені суми дебетів і кредитів до дня включно,
  NUMERIC(38,18), валюта рахунку) і `balance_versions` (версія рахунку, найпізніший час запису в кеші). Накопичені
  суми, а не рух за день: баланс на дату — один рядок; запис заднім числом додає рух до свого дня і всіх пізніших.
  Кеш не журнал: змінюється на місці, роль модуля має на ньому SELECT, INSERT, UPDATE, DELETE.
- Рішення ведучого (2026-11-13; власник не схвалював; цей PR): перевірка версії — `UPDATE … WHERE version = $n` у
  транзакції запису, по рахунках у порядку ідентифікаторів (без взаємних блокувань); конфлікт повторюється на свіжій
  версії до 5 разів, далі `BALANCE_CONFLICT` і відкат запису. Рахунок без кешу будується з проводок під час першого
  запису на ньому.
- Рішення ведучого (2026-11-13; власник не схвалював; цей PR): застарілий кеш не віддається і не пишеться: читання —
  одна інструкція (версія і день з одного знімка); без кешу або з «як було відомо на момент» раніше за найпізніший
  запис у кеші відповідає сума проводок; тригер обмеження під час коміту відхиляє проводку на рахунку з кешем без
  зміни кешу (стара версія коду чи прямий INSERT); щоденна перевірка цілісності отримала вид `balance-cache`
  (кількість рахунків, без сум) — вимога ARC-11 «кеш залишків дорівнює сумі проводок».
- Рішення ведучого (2026-11-13; власник не схвалював; цей PR): команда перебудови — `Ledger.rebuildBalances` і скрипт
  `scripts/ledger-balances.ts rebuild <простір> [<рахунок>]` роллю модуля (журнал не змінюється, друкує лише
  кількості). Без запису аудиту: дані простору не змінюються, лише похідний кеш. Без прапорця функції: це не нова
  функція для користувача, а спосіб обчислення балансу з тими самими числами (тест властивостей). Міграція не заповнює
  кеш наявних даних (сервер не розгорнуто, даних у журналі ще немає): рахунки без кешу
  відповідають сумою проводок, перший запис або команда перебудови будують кеш.
