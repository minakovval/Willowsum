# FLW-44 / BUD-19: кредитна картка в плані погашення — рішення реалізації

**Створено:** 2026-11-27

Код за рішенням власника 2026-11-27 (`2026-11-27-flw44-credit-card-plan.md`). Дрібні рішення реалізації, власник їх не
погоджував:

- Рішення ведучого (2026-11-27; власник не схвалював; FLW-44 code): сума картки «Зменшувати на … / міс.» — це регулярний
  платіж збереженого плану картки (`debt_payoff.plans.monthly_payment`, ставка плану 0). «Зберегти план» зберігає суму,
  видалення плану її прибирає. Нової таблиці і міграції немає; API віддає суму новим полем `cardMonthlyAmount` у
  `GET /v1/debts` (нове поле, жодне наявне перелічення не змінено — ARC-07 FR 3).
- Рішення ведучого (2026-11-27; власник не схвалював; FLW-44 code): у картки в `GET /v1/debts` поля `annualRate` і
  `monthlyPayment` — null, навіть якщо рахунок має ставку (FIN-01): у плані ставки картки немає. Ставка для картки в
  сценарії, плані чи стратегії — 400 `not_applicable`.
- Рішення ведучого (2026-11-27; власник не схвалював; FLW-44 code): на «Стратегії» картку без суми можна врахувати,
  ввівши суму в полі «Зменшувати на … / міс.: {назва}» (як мінімальний платіж боргу без платежу; не зберігається).
- Рішення ведучого (2026-11-27; власник не схвалював; FLW-44 code): попередження «суми не вистачає» — наявне
  «Сума менша за мінімальні платежі ({min})» (сервер: 400 `total: below_minimums`), тепер з платежем картки в мінімумах.
- Рішення ведучого (2026-11-27; власник не схвалював; FLW-44 code): картка без суми в підсумку «Без боргів» названа
  після «крім:», як інші борги без розрахунку.
- Збережений раніше план картки зі ставкою (до цього рішення) рахується далі як сума без відсотків; його власна
  записана ставка лишається в плані (лише синтетичні дані).
