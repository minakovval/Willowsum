# Рішення власника 2026-11-27: вимога без нумерованих пунктів — «немає пунктів для підрахунку» на сторінці ходу

**Створено:** 2026-11-27 · **Оновлено:** 2026-11-27

- Рішення власника (2026-11-27, чат): «так» на рекомендацію ведучого, варіант 3, перша частина. Вимога релізу PoC без нумерованих пунктів FR/AC/EC (`items.total = 0`; на сьогодні ARC-11, CICD-02, CICD-04, JRN-05, JRN-06) не показується як «не почато».
- Друга частина варіанта 3 (пронумерувати пункти цих п'яти вимог) — окремий PR; `docs/requirements` тут не змінено.

## Що змінено

- `node tools/req-check/index.mjs --coverage-json`: новий статус функції «немає пунктів для підрахунку» (константа `NO_ITEMS` у `tools/req-check/lib/coverage.mjs`), коли в поданні PoC немає жодного FR, AC чи EC. Помилка відбитків цей статус не змінює. Форма файлу (`schema: 1`, `version: 2`) без змін; додано лише нове значення поля `status`.
- Сторінка `tools/progress-dashboard/index.html`: такий статус — окремий значок із пунктирною рамкою і рядок «У тексті вимоги немає нумерованих пунктів, готовність не вимірюється.» замість відсотка. Такі функції не входять у «Готово N з M» (ні в блоці, ні в підсумку) і не впливають на відсоток блоку; рядок-примітка під заголовком каже, скільки їх і що їх не враховано. Відкритий PR із назвою «ID: …» цей статус не змінює (піднімає лише «не почато»). Блок, де всі функції такі, має той самий статус.
- Тести: `tools/req-check/test/source.test.mjs`, `tools/req-check/test/blocks.test.mjs` (на реальних вимогах репозиторію), `tools/pr-rules/test/workflows.test.mjs` (логіка сторінки).
- Знімок 1280 px із реальними даними: `docs/validation/screenshots/dash-no-items.png`.

## Ризики, мінуси

- Стара сторінка (кешована в браузері) з новим `coverage.json` відкидає функції з новим статусом як незнайомі; оновлення сторінки це виправляє, бо CI публікує сторінку і файл разом.
