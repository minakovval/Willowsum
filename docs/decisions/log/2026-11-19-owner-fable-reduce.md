## Питання 1: як скоротити Fable

Питання ведучого, дослівно (з варіантами):

> **1. Як скоротити Fable?**
> - а) Fable лишається лише для **першої рецензії безпеки PR з `sensitive:money`, `permissions`, `auth` або `crypto`**. Підтвердження (раунд 2, синхронізації) і PR лише з `sensitive:pipeline` чи `infra` переходять на Opus зі skill `security-review`. Fable — не більше 2 агентів одночасно. **(раджу)** Ризики: Opus слабше ловить тонкі обходи на підтвердженнях. Мінуси: дві моделі на одному PR — різні стандарти. Як пом'якшити: якщо підтвердження додає guard, ендпоінт чи запит (повна рецензія за §7), її робить Fable.
> - б) Fable лише для auth, permissions і crypto; гроші переходять на Opus. Ризики: помилки в сумах і курсах частіше доходитимуть до main. Мінуси: найбільший ризиковий модуль без найсильнішої рецензії. Як пом'якшити: обов'язкове мутаційне тестування для money.
> - в) Без Fable, усе на Opus. Ризики: найслабша перевірка безпеки. Мінуси: пропущене знайдеться пізніше й дорожче. Як пом'якшити: щотижневий прохід Fable по злитих sensitive PR.

Відповідь власника (2026-11-19, чат ведучого), дослівно: «1а»

Рішення власника (2026-11-19): 1а — Fable лише для першої рецензії безпеки PR з `sensitive:money`, `sensitive:permissions`, `sensitive:auth` або `sensitive:encryption` (у питанні — `crypto`; у CI така категорія зветься `encryption`). Підтвердження (раунд 2, синхронізації) і PR лише з `sensitive:pipeline` чи `infrastructure` (у питанні — `infra`) — на Opus зі skill `security-review`. Fable — не більше 2 завдань одночасно (було 4). Якщо підтвердження додає guard, ендпоінт чи запит, це повна рецензія за `security-review` §7, і її робить Fable. Лишається за правилами 2026-11-16: проєктування A1 з поправками до ADR-0002 і ADR-0015 та планування хвилі (`plan-wave`).

- Ризик: Opus слабше ловить тонкі обходи на підтвердженнях. Пом'якшення: підтвердження з новим guard, ендпоінтом чи запитом іде на Fable; мутаційне тестування критичних модулів обов'язкове на будь-якій моделі.
