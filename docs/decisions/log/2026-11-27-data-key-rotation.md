# Заміна ключів даних просторів, створених під ключем фіксованої мітки (NFR-01@PoC п. 3, NFR-15@PoC п. 26)

**Створено:** 2026-11-27

Привід: безпековий огляд PR #726 (follow-up «data keys of spaces made under the fixed-label key are not replaced after
the move»). Переобгортання (`kms:rewrap`) змінює обгортку, а не ключ даних: копія бази, зроблена до нього, разом із
репозиторієм відкривала б і значення, запечатані пізніше.

Рішення ведучого (2026-11-27; власник не схвалював; цей PR): дрібні деталі, вирішені в PR.

- **Які простори.** Ключ має позначку `space_keys.exposed`. Чи був ключ колись обгорнутий ключем фіксованої мітки,
  раніше не записувалось, тож усі ключі, що існували до міграції `household/0005`, і всі ключі, які вставляє попередній
  код, вважаються такими (значення за замовчуванням `true`). Новий код ставить `false` ключу, вперше обгорнутому іншим
  головним ключем (файл ключа інсталяції). Зайва заміна безпечна, пропущена — ні.
- **Як.** Новий ключ даних обгортається ключем інсталяції; кожен модуль із запечатаними значеннями (accounts,
  import-recipes, import-sessions, file-storage) дає «частину» (`ResealPart`, тип у `platform/modules/reseal.ts`, щоб
  правила залежностей модулів не змінювались), яка пакетами по 100 значень (байтові — до 8) у транзакції ролі свого
  модуля відкриває значення старим ключем і запечатує новим. Значення, яке вже відкривається новим ключем, лишається як
  є: повтор після зупинки нічого не запечатує двічі. Наприкінці, під замком запису простору, новий ключ стає на місце
  старого, обгортка старого видаляється (ключ «виведено»), у журналі простору — `household.space-key` `create` (новий)
  і `delete` (старий).
- **Відновлення після збою.** Новий ключ (лише його обгортка) і завершені частини — у таблиці `space_key_rotations`.
  Поки рядок є, простір не запечатує й не відкриває значень (`SPACE_KEY_ROTATING`, новий код у `SPACE_KEY_ERROR_CODES`,
  у контракт API не входить): інакше програма, запущена посеред заміни, запечатала б нове значення старим ключем, і його
  втратили б після виведення старого ключа. Знищення ключа простору видаляє й рядок заміни.
- **Запуск.** `pnpm local:dev --rotate-data-keys [--dry-run]`: готує базу як звичайний старт (зокрема переобгортання),
  тримає замок кластера і не запускає жодного процесу — програма зупинена, поки команда працює. Вручну —
  `pnpm --filter @willowsum/api kms:rotate-data-keys [--dry-run] [--batch-size N]` з конфігурацією процесів. Без
  `WS_REAL_DATA=true` і файлу ключа команда відмовляється (вихід 2); файлу ключа не створює. Звіт — лише лічильники.
- **Після заміни** власник видаляє всі копії бази, зроблені до неї, і робить нову (`infra/local/README.md`). Файл ключа
  інсталяції не змінюється.
