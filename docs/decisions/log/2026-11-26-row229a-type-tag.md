# Рішення ведучого 2026-11-26: тег типу в списку транзакцій (рядок 229a)

**Створено:** 2026-11-26

Дрібні рішення під час виконання рядка 229a (FIN-03@PoC FR 13, AC 23); вимоги не змінено. Власник їх не схвалював.

- Рішення ведучого (2026-11-26; власник не схвалював; row 229a): тип береться з наявних даних списку без нового
  запиту й без змін сервера: «переказ» — якщо у відповіді є `transfer` (підтверджений переказ, ручна пара,
  позначка «Це переказ» — усе це запис `transfer`), інакше `type` транзакції («витрата» для `expense`, «дохід» для `income`).
- Рішення ведучого (2026-11-26; власник не схвалював; row 229a): тег стоїть під сумою, по правому краю клітинки
  суми (дрібний приглушений текст у `ws-row-money`), а не перед нею: рядок не росте по висоті (клітинка дати вже в два
  рядки) і сума лишається вирівняною праворуч. Пропс `type` компонента `TransactionRow` необов'язковий: картка рахунку
  й черга «До розбору» тег не показують.
- Рішення ведучого (2026-11-26; власник не схвалював; row 229a): для екранного читача тип дописано до назви рядка після
  суми («…, мінус 12,50 євро, витрата»); для переказу не дублюється, бо його вже називає бейдж «переказ» біля контрагента.
- Тексти «витрата», «дохід», «переказ» уже стоять у блоці «Тексти» S-046 канви з позначкою «варіант від агента,
  потребує погодження» (PR #705); нових текстів немає. Ключі `transactionRow.type.*` у uk і en.
