# Рішення 2026-11-14: шардинг інтеграційних тестів у CI (2 шарди) — виконано

**Створено:** 2026-11-14 · **Оновлено:** 2026-11-14

- Рішення власника (2026-11-14): схвалено шардинг інтеграційних тестів у CI (2 шарди) окремим PR `sensitive:pipeline`
  після #229 (#229 закрито в #231). Слова власника (чат ведучого 4): «так, 1–4 так, пункт 3 як пробні 2 запуски».
  Джерело: [#178, коментар 6883729022](https://github.com/minakovval/Willowsum/issues/178#issuecomment-6883729022),
  пункт 2.
- Статус: виконано в PR «CICD-02: run the api integration tests in 2 vitest shards behind the check `api`»
  (гілка `claude/adoring-cray-feh4dh-ci-shard`). У `.github/workflows/pr-checks.yml` матрична задача `api-parts`
  має три паралельні частини, кожна зі своїм сервісом PostgreSQL 17: `api checks` (усе, крім інтеграційних тестів)
  і `api integration 1/2`, `api integration 2/2` (`vitest --shard=i/2`, поділ за файлами). Обов'язкова перевірка
  лишається `api`: невелика задача, що чекає частини й падає, якщо хоч одна не `success`; фільтр шляхів пропускає
  її разом із частинами. `tools/pr-rules/lib/workflows.mjs` не рахує обов'язковою матричну задачу, яку потребує
  інша задача, тож перелік обов'язкових задач в AGENTS.md і щоденна перевірка `main` не змінюються.
- Рішення реалізатора (2026-11-14; власник не схвалював): перевірки без інтеграційних тестів винесено в третю
  паралельну частину `api checks`, а не залишено в `api` після шардів, — інакше `api` чекала б шарди і тривалість
  майже не зменшилась би. Ліміт часу частини лишився 30 хв ([2026-11-14-ci-api-timeout-30.md](2026-11-14-ci-api-timeout-30.md)).
- Ризики та заходи (спільні ролі кластера, нестабільні тести, хвилини CI) — в описі PR.
