Аудит лише для читання (issue #32). Джерела: вимоги `origin/main` (робоча копія `wt-a2`, після аудиту видалена), полотно `project/*.dc.html` (усі 299 артбордів, копія в `scratchpad/canvas-all/project`), README компонентів дизайн-системи (`scratchpad/new/project/components/*/README.md`). Шляхи вимог нижче відносні до `docs/requirements/`; назви артбордів без `.dc.html`.

Позначки: **ДС** — README компонента в дизайн-системі; **полотно** — артборди; «Poc*» — сторінка PoC полотна, без префікса — сторінки «Гроші»/«Планування»/«Системні» (обсяг MVP).

> Головне спостереження. Для більшості елементів цієї області є **три різні «еталони»**: текст CMP-вимоги (`cmp/CMP-xx.poc.md`), README ДС (який описує полотно P0) і саме полотно. ДС і полотно здебільшого збігаються між собою, а CMP-вимоги описують старіший вигляд (44 px, радіус 4 px, рамка 1,5 px `border-control`, нативний `select`, смуга банера 6 px тощо). Тому в стовпці «Що змінити» спершу треба вирішити, що є еталоном (див. рішення в кінці).

## Рішення, які треба ухвалити (еталон неоднозначний)

1. **Хто еталон розмірів: CMP-вимога чи ДС/полотно.** Для Select (44 px / r4 / 1,5 px / нативний) проти 40 px / r8 / 1 px, Segmented (рамка + заливка `brand`) проти сірої доріжки, Dialog (плитка 48/r8, кнопки без висоти, розмиття 4 px) проти 56/r16, 48/r10, 2 px, Toast (r4) проти r8. Рекомендую: взяти ДС і полотно за основу і переписати `cmp/CMP-03`, `CMP-12`, `CMP-14`, `CMP-19`, `CMP-20`, `CMP-21` (`.poc.md` і `.mvp.md`), лишивши вимоги доступності з CMP (рамка `border-control` 3 : 1, зона 44 px, кільце фокуса 3 px).
2. **Банер: смуга 6 px, смуга 3 px чи без смуги.** CMP-19 і DS-06 кажуть «смуга», ДС README — «без смуг», полотно — 3 px без маркера. Рекомендую: смуга 3 px (як на полотні) **плюс** маркер тону і слово з CMP-19 / DS-07. Окремо вирішити, чи вбудована підказка (рядок 22) — варіант банера.
3. **Кнопки смуги діалогу: 48 px r10 (короткі діалоги) чи 40 px r8 (форми) — один розмір чи два.** Зараз це дві родини без правила. Рекомендую один розмір для всіх діалогів; якщо два — записати в CMP-21 («рішення» 48 px, «форма» 40 px).
4. **Стан «пройдений» у індикаторі кроків: `gain` (#27704C, CMP-21 п. 8, полотно) чи `brand-2` (#1D4E89, CMP-14); кроки натискаються чи ні.** Рекомендую CMP-21 п. 8 (натискаються, `gain`) і переписати CMP-14; сторінка-майстер — той самий компонент у розмірі `page`.
5. **«Скасувати» на кроках 2+ крокового діалогу.** CMP-21 п. 7 вимагає, полотно прибирає. Рекомендую лишити (вихід без Esc і без «✕» потрібен на кожному кроці).
6. **«Підсумок періоду» (S-135): PeriodPicker чи бюджетна навігація.** CMP-72 і BUD-02 суперечать. Рекомендую бюджетну навігацію (це вигляд минулого періоду бюджету) і прибрати «підсумок періоду» з Призначення CMP-72; бюджетну навігацію описати як режим CMP-72 без «Тип періоду».
7. **Перемикач періоду графіка: бордований Segmented чи «тихий».** Полотно скрізь тихе, CMP-12 вимагає бордований. Рекомендую тихий варіант як офіційний `quiet` у CMP-12 (заголовок картки = заголовок віджета) і одну ARIA-модель (`radiogroup`).
8. **Поле з пошуком і поле дати.** Компонентів немає, правила розкидані по FIN-03, BUD-12, BUD-01. Рекомендую розширити CMP-03 (варіант «з пошуком») і CMP-02 (тип «дата» з календарем), а не робити нові CMP; перша група списку категорій — «Часто для <мерчанта>», коли мерчант відомий, інакше «Нещодавні».
9. **Форма в поповері.** CMP-61 забороняє, DS-01 п. 24 і BUD-18 вимагають. Рекомендую дозволити поповер для 1–3 значень без незворотних наслідків і зафіксувати його стиль у CMP-61; «Оновити залишок» лишити модальним як «підсумок «Що зміниться»».
10. **Ширина понад 560 px.** Рекомендую рішення власника: або розмір `wide` (наприклад 900 px) для порівняння «оригінал — розпізнане» (MoneyReceipt, MoneyPairManual) і 640 px для розділення, або окремі сторінки.
11. **Тости: одне повідомлення чи стос; 6 с чи 8/10 с.** Рекомендую CMP-20 (одне, 8/10 с) і виправити DS-09 та токен `duration-toast`.
12. **Слово для відміни дії.** «Скасувати» одночасно закриває діалог, відміняє дію і позначає платіж. Рекомендую в DS-03 закріпити: «Скасувати» — лише закрити без змін; відміна виконаної дії — «Відмінити» (у тості й кнопці сторінки).
