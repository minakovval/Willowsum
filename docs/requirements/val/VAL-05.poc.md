**Мета.** Як власник акцій, криптовалюти та активів у валюті, я хочу, щоб ціни та курси оновлювалися автоматично, щоб не вводити їх вручну.

**Функціональні вимоги**
1. Щоденне фонове завдання завантажує курси всіх підтримуваних валют.
2. Курси оновлюються раз на добу.
3. Джерела курсів: ECB для основних валют, НБУ для гривні.
4. Якщо провайдер недоступний, завдання виконує повторні спроби. Якщо успішного оновлення немає 24 год, команда отримує алерт моніторингу. Користувачі бачать останні успішні значення з позначкою дати останнього оновлення.
5. Провайдери курсів підключаються через абстракцію провайдера; під час зміни провайдера користувачі не бачать змін.

**Бізнес-правила**
- Курси валют надходять щоденним фідом з історією через абстракцію провайдера.
- Кожна сума зберігається в оригінальній валюті; конвертація лише під час відображення і зберігає використаний курс, дату і джерело.
- Абстракція провайдерів: джерела курсів підключаються через один інтерфейс і замінюються без змін у клієнтах; збій зовнішнього провайдера не блокує перегляду даних.

**Права доступу:** фонова функція без дій користувача; результати бачить користувач простору.

**Ліміти плану:** планів немає; курси оновлюються раз на добу.

**Стани інтерфейсу**
- Фід не оновлювався — біля сум «оновлено <дата і час>».

**Критерії приймання**
1. **Given** настав час щоденного оновлення, провайдер доступний **When** запускається щоденне завдання **Then** завантажено курси всіх підтримуваних валют.
2. **Given** провайдер не відповідає **When** завдання не виконане **Then** виконуються повтори; через 24 год без успіху команда отримує алерт, користувачі бачать дату останнього оновлення.
3. **Given** старий провайдер курсів активний **When** команда підключає нового через абстракцію **Then** користувачі не бачать змін.
4. **Given** провайдер недоступний **When** користувач відкриває список рахунків **Then** суми показано за останніми успішними курсами, перегляд не блокується.

Припущення: повторні спроби — щогодини до успішного завантаження.
