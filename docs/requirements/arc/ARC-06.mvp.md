1. Конвертне шифрування: кожен простір має власний ключ даних (AES-256-GCM), обгорнутий головним ключем. Доступ до головного ключа — лише через адаптер KMS, що викликає керований KMS. Хостинг і резервні копії працюють за профілем «Старт», а головний ключ живе в керованому KMS хмари хостингу (OCI Vault в Oracle Cloud Infrastructure): значення ключа не залишає KMS, копій поза KMS немає.
2. Поля з особливо чутливими даними (IBAN, номери полісів) шифруються окремо ключем простору. Токен провайдера зберігається в БД, зашифрований окремим ключем підключення (AES-256-GCM), обгорнутим ключем простору; головний ключ — лише через порт KMS. Токен лише записується: API його не повертає, у формі видно тільки останні 4 символи. Заміна токена і відключення одразу знищують ключ підключення (крипто-видалення, включно з копіями). Для monobank діалог відключення пояснює, як відкликати токен у кабінеті monobank.
3. Секрети не зберігаються в репозиторії, образах, логах і документації. Ротація головного ключа — щонайменше раз на рік, без простою (переобгортання ключів просторів у фоні). Перша ротація головного ключа в production — лише після репетиції з хмарним KMS на тимчасовому середовищі форми production.
4. Файли користувачів зберігаються в S3-сумісному сховищі зашифрованими ключем простору; доступ — лише через підписані посилання із коротким строком. Перед доступністю файл перевіряє антивірус.
5. Видалення простору знищує його ключ; дані зникають із резервних копій із їхньою ротацією (≤ 35 днів).

| Критерій | Поріг | Перевірка |
| --- | --- | --- |
| Секрети в історії git і образах | 0 | Сканер секретів на кожному PR і щотижня по всій історії |
| Файл, доступний без підписаного посилання | 0 | Тест на тимчасовому середовищі форми production і перевірка після кожного розгортання: анонімний запит до бакета production (список і об'єкт) отримує відмову |
| Ротація головного ключа | Без простою, раз на рік | Репетиція на тимчасовому середовищі форми production |
