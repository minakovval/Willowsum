1. Один образ контейнера запускається в трьох ролях: API, воркер фонових задач, планувальник задач за розкладом. Роль задає команда запуску.
2. Процеси не зберігають стану в пам'яті чи на диску між запитами; будь-який екземпляр можна зупинити або додати без втрати даних.
3. Конфігурація — лише змінні середовища та секрети, перевірені схемою під час старту. З некоректною конфігурацією процес не стартує.
4. Кожен процес має перевірки «живий» і «готовий»; «готовий» перевіряє з'єднання з БД і версію схеми.
5. Зупинка процесу — коректна: API довершує запити до 30 с, воркер повертає незавершені задачі в чергу.
