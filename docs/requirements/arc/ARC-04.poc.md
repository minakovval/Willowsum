1. Черга задач зберігається в PostgreSQL; окремий брокер повідомлень не використовується. Інтерфейс черги дозволяє замінити її на керовану чергу без змін у модулях.
2. Події між модулями публікуються в тій самій транзакції БД, що й зміна даних (таблиця вихідних подій). Подія не втрачається і не публікується для відкоченої зміни.
3. Кожна задача ідемпотентна: повторне виконання дає той самий результат.
4. Повтори з експоненційною затримкою, до 8 спроб; після цього задача потрапляє в чергу невдалих, а в журнал сервера пишеться подія рівня «помилка» без даних простору.
5. Діє один спільний ліміт одночасних важких задач (імпорт) у воркері; розподілу між просторами в цьому релізі немає. Інтерфейс черги дозволяє додати його без переробки.
