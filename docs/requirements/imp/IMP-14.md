# IMP-14 · Файл помилок і повторний імпорт виправлених рядків

**Реліз:** PoC (без колонки сторінки для PDF і сканів і без вбудованого профілю «Файл помилок»); PoC v2 (вбудований профіль «Файл помилок» з підстановкою рахунку і позначкою «виправлення партії …»); MVP (ролі й учасники простору; колонка «сторінка» для PDF і сканів) · **Пріоритет:** M

**Зв'язки**
- Зрізи: IMP-14@PoC, IMP-14@PoC v2, IMP-14@MVP
- Модуль: file-storage, import-sessions

**Мета.** Як учасник, що імпортує виписку, я хочу отримати рядки, які не вдалося імпортувати, виправити їх і додати, щоб не втратити жодної операції.

**Релізні зрізи.** Кожен зріз повний для свого релізу: функціональні вимоги, правила, права, стани і критерії приймання, що діють у ньому, без посилань на інші зрізи. Зріз діє до релізу наступного зрізу.

**Функціональні вимоги**
#. [PoC] Система повинна формувати файл помилок CSV для кожного файлу партії, у якому хоча б один рядок не став транзакцією через помилку. Службові рядки (підсумки, шапки, перенесення залишку) і дублі до нього не потрапляють: вони є в звіті імпорту з причиною.
#. [PoC–PoC v2] Колонки файлу помилок: номер рядка в оригіналі, поле з помилкою, код і текст причини мовою інтерфейсу, а далі — колонки дата, сума, валюта, опис, залишок із значеннями як у оригіналі та службовий ідентифікатор партії. Кодування UTF-8 із BOM, роздільник — кома.
#. [MVP] Колонки файлу помилок: номер рядка в оригіналі, сторінка (для PDF і сканів), поле з помилкою, код і текст причини мовою інтерфейсу, а далі — колонки дата, сума, валюта, опис, залишок із значеннями як у оригіналі та службовий ідентифікатор партії. Кодування UTF-8 із BOM, роздільник — кома.
#. [PoC] Файл помилок доступний з екрана результату імпорту і з історії імпортів тим, хто бачить партію, через підписане посилання зі строком дії 15 хв. Він зберігається зашифрованим і живе стільки ж, скільки оригінал файлу.
#. [лише PoC] Вбудованого профілю «Файл помилок» немає: виправлені рядки користувач додає звичайним імпортом, сам обираючи рахунок і шаблон; рахунок початкової партії не підставляється, а нова партія не позначається як виправлення початкової. Рядки проходять ті самі перевірки, що й будь-який імпорт, включно з пошуком дублів.
#. [PoC v2] Виправлений файл помилок завантажується звичайним імпортом. Рушій розпізнає його за шапкою, застосовує вбудований профіль «Файл помилок», пропонує рахунок початкової партії і позначає нову партію як «виправлення партії …».
#. [PoC v2] Рядки виправленого файлу проходять ті самі перевірки, що й будь-який імпорт, включно з пошуком дублів. Звірка залишку для нього не виконується; партія позначається «залишок не перевірявся».

**Критерії приймання**
#. [PoC] **Given** файл із 120 рядків, з яких 3 мають нечислову суму і 2 є підсумками **When** імпорт застосовано **Then** файл помилок містить рівно 3 рядки з номерами в оригіналі і причиною «сума не є числом», а підсумки є лише в звіті.
#. [лише PoC] **Given** 3 виправлені рядки з файлу помилок імпортовано звичайним імпортом на той самий рахунок **When** той самий файл завантажено вдруге **Then** усі 3 рядки позначено дублями, нових транзакцій немає, а профілю «Файл помилок» серед шаблонів немає.
#. [PoC v2] **Given** виправлений файл помилок із 3 рядками **When** його завантажено **Then** рахунок початкової партії запропоновано, імпортовано 3 транзакції, нова партія зв'язана з початковою.
#. [PoC v2] **Given** той самий виправлений файл завантажено вдруге **When** рушій його обробляє **Then** усі 3 рядки позначено дублями, нових транзакцій немає.
#. [PoC–PoC v2] **Given** простір, у якому єдиний користувач — Owner **When** запит на файл помилок партії надходить від користувача, що не належить до цього простору **Then** сервер відповідає «не знайдено» і не розкриває записів, кількостей чи сум простору.
#. [MVP] **Given** обмежена партія **When** Editor без доступу до неї запитує файл помилок **Then** він отримує «не знайдено».
