# PRC-01 · Процес вимог: релізні зрізи, зв'язки й трасування

**Реліз:** PoC · **Пріоритет:** M

**Зв'язки**
- Зрізи: PRC-01@PoC
- Модуль: —

**Мета.** Як власник продукту, я хочу, щоб вимоги кожного релізу читалися й будувалися лише з власних зрізів, були пов'язані явними залежностями з послідовністю збирання і трасувалися до дизайну, спільних правил, сценаріїв і тестів, щоб реліз можна було планувати, будувати й перевіряти без пошуку по всіх вимогах.

**Релізні зрізи.** Кожен зріз повний для свого релізу. Зріз діє до релізу наступного зрізу.

## Джерело зрізів

**Реліз:** PoC · **Пріоритет:** M

**Зв'язки**
- Розширює: —
- Залежить від: CICD-01@PoC, CICD-02@PoC
- Дизайн: —
- Спільні правила: ARC-01, NFR-19
- Сценарії: —
- Модуль: —
- Перевіряється: tools/req-check/test/links.test.mjs, tools/req-check/test/traceability.test.mjs

**Мета.** Як власник продукту, я хочу, щоб вимоги кожного релізу читалися й будувалися лише з власних зрізів, були пов'язані явними залежностями з послідовністю збирання і трасувалися до дизайну, спільних правил, сценаріїв і тестів, щоб реліз можна було планувати, будувати й перевіряти без пошуку по всіх вимогах.

**Функціональні вимоги**
#. [PoC] Релізи в порядку збирання: PoC, PoC v2, MVP, v1-mobile, v1, v2. Сейф входить у MVP і окремим релізом не є.
#. [PoC] Мігрована вимога складається з картки `<папка модуля>/<ID>.md` і одного файлу зрізу на кожен реліз, у якому змінюється її обсяг: `<ID>.<ключ>.md`, де ключ — `poc`, `poc-v2`, `mvp`, `v1-mobile`, `v1` або `v2`. Зріз позначається `<ID>@<реліз>`, наприклад `<ID>@PoC v2`. Ідентифікатор вимоги стабільний і не змінюється під час міграції.
#. [PoC] Картка містить заголовок `# <ID> · <назва>`, рядок «Реліз» з усіма релізами зрізів, блок «Зв'язки» з полями «Зрізи» і «Модуль», мету і таблицю зрізів з посиланнями на файли та коротким описом того, що змінює кожен зріз. Функціональних вимог і критеріїв приймання картка не містить. Рядок «Реліз» картки збігається з рядком таблиці вимог у README модуля.
#. [PoC] Зріз має заголовок `# <ID>@<реліз> · <назва>` з назвою картки, рядок `**Реліз:** <реліз> · **Пріоритет:** <пріоритет картки>`, блок «Зв'язки» і далі текст вимоги: мету, функціональні вимоги, бізнес-правила, права доступу, ліміти плану, стани інтерфейсу, критерії приймання і граничні випадки, що діють у цьому релізі.
#. [PoC] Зріз повний для свого релізу: він не містить блоків «У релізі …» і не вимагає читати інші зрізи. Пізніший зріз повторює все, що зберігає з попереднього, і додає нове; зріз діє до релізу наступного зрізу тієї самої вимоги.
#. [PoC] Зріз створюється для кожного релізу з рядка «Реліз» вимоги, а також для релізу, з якого починає діяти поведінка, яку загальні правила виключають з попередніх релізів (обмеження PoC і PoC v2, застосування лімітів планів з v1). Обсяг, перенесений рішенням власника в пізніший реліз, вилучається з ранішого зрізу і додається в пізніший.
#. [PoC] Блок «Зв'язки» стоїть одразу після рядка «Реліз». Кожне поле — окремий рядок `- <поле>: <ID>, <ID>`; порожній перелік записується як `- <поле>: —`. Поля зрізу, у цьому порядку: «Розширює», «Залежить від», «Дизайн», «Спільні правила», «Сценарії», «Модуль», «Перевіряється».
#. [PoC] Значення полів: «Розширює» — зріз тієї самої вимоги в попередньому релізі, де вона має зріз, а для першого зрізу — «—»; «Залежить від» — зрізи інших вимог того самого або ранішого релізу (вимогу без релізу вказують ідентифікатором), і саме той зріз, що діє в релізі залежного зрізу; «Дизайн» — ідентифікатори екранів карти екранів і назви бордів канваса; «Спільні правила» — загальні правила П-n і вимоги дизайн-системи, компонентів, сітки, графіків, архітектури, нефункціональні, поставки, процесу, локалізації й екранів, що діють не пізніше релізу зрізу; «Сценарії» — ідентифікатори сценаріїв використання; «Модуль» — назви модулів з каталогу модулів архітектури; порожнім поле може бути лише у вимог спільних областей — дизайн-системи, компонентів, сітки, графіків, архітектури, нефункціональних, поставки, процесу, локалізації й екранів; поле «Модуль» картки — це всі модулі її зрізів; «Перевіряється» — шляхи до тестів у репозиторії.
#. [PoC] Ідентифікатори інших вимог дозволені лише в блоці «Зв'язки». Решта тексту картки і зрізу самодостатня, як і раніше.
#. [PoC] Нова вимога отримує наступний вільний ідентифікатор свого модуля, який ніколи не використовувався. Вона одразу створюється як картка зі зрізами і додається в таблицю README модуля і в таблицю модулів загального README з кількістю вимог і розподілом за релізами.
#. [PoC] Зміна вимоги виконується одним PR, який змінює картку, усі зачеплені зрізи, їхні зв'язки і рядок README модуля. Тіло PR фіксує рішення власника, яке зміна реалізує; без цього PR не зливається.
#. [PoC] Перевірка вимог зупиняє PR, якщо: ідентифікатор у зв'язках не існує (вимога, зріз, екран, сценарій, правило П-n, модуль, шлях тесту); зріз залежить від зрізу пізнішого релізу або від зрізу, що в його релізі вже замінений новішим; залежності утворюють цикл; «Розширює» вказує не попередній зріз тієї самої вимоги; перелік «Зрізи» картки або релізи її рядка «Реліз» не збігаються з файлами зрізів; «Модуль» картки не дорівнює модулям її зрізів; поле відсутнє, зайве або стоїть не на своєму місці.
#. [PoC] Перевірка вимог з ключем `--traceability` генерує папку `docs/traceability`: матрицю (рядок на кожен зріз: реліз, стан, модуль, «Розширює», залежності, дизайн, спільні правила, сценарії, тести, кількість критеріїв), файл кожного релізу (перелік зрізів, граф залежностей і послідовність збирання хвилями) і файл покриття (екрани релізу без зрізу, зрізи без дизайну, зрізи без критеріїв). Згенеровані файли комітяться в тому самому PR; конвеєр перевірки PR генерує їх заново і зупиняє PR, якщо результат відрізняється.
#. [PoC] Ще не мігрована вимога діє як один неявний зріз на кожен реліз її рядка «Реліз», без зв'язків; у матриці вона позначена «не мігровано», а в послідовності збирання стоїть окремим переліком без місця. Сегменти рядка «Реліз» розділяються знаками «;» і «·» поза дужками; неявний зріз створює лише сегмент, що починається з релізу («MVP (…)») або закінчується ним («решта — MVP»). Реліз, згаданий лише в дужках («PoC (…; push — v1-mobile)»), зрізу не створює; сегмент «основа в архітектурі й моделі даних — <реліз>» теж.
#. [PoC] Вимоги мігрують пакетами, по модулю або групі пов'язаних модулів на PR, від ранніх релізів до пізніх; кожен пакет проходить усі перевірки сам.

**Бізнес-правила**
- [PoC] Зміст вимоги під час міграції не змінюється: міграція лише розкладає наявний текст на зрізи й додає зв'язки. Будь-яка зміна поведінки — окреме рішення власника.
- [PoC] Критерії приймання кожного зрізу нумеруються з 1 і мають форму Given / When / Then.
- [PoC] Згенеровані файли не редагуються вручну.

**Ролі**
- [PoC] Власник продукту ухвалює зміни вимог і перенесення обсягу між релізами.
- [PoC] AI-агент виконує міграцію і зміни вимог у PR; рев'ю робить окрема сесія.

**Критерії приймання**
#. [PoC] **Given** зріз релізу PoC, у полі «Залежить від» якого вказано зріз іншої вимоги релізу MVP **When** запускається перевірка вимог **Then** вона завершується помилкою про залежність від пізнішого релізу, і PR не проходить.
#. [PoC] **Given** два зрізи, кожен з яких залежить від іншого **When** запускається перевірка вимог **Then** вона завершується помилкою про цикл залежностей з переліком зрізів циклу.
#. [PoC] **Given** вимога має зрізи PoC і PoC v2, а «Розширює» зрізу PoC v2 порожнє **When** запускається перевірка вимог **Then** вона завершується помилкою: «Розширює» має вказувати зріз PoC тієї самої вимоги.
#. [PoC] **Given** у полі «Дизайн» зрізу вказано екран, якого немає в карті екранів **When** запускається перевірка вимог **Then** вона завершується помилкою з ідентифікатором цього екрана.
#. [PoC] **Given** ідентифікатор іншої вимоги в тексті зрізу поза блоком «Зв'язки» **When** запускається перевірка вимог **Then** вона завершується помилкою самодостатності; той самий ідентифікатор у блоці «Зв'язки» помилки не дає.
#. [PoC] **Given** зв'язки зрізу змінено, а файли трасування не згенеровано заново **When** конвеєр перевіряє PR **Then** крок трасування завершується помилкою і показує різницю.
#. [PoC] **Given** не мігрована вимога з рядком «Реліз» «PoC (…); решта — MVP» **When** генерується матриця **Then** вимога має два рядки, для PoC і для MVP, зі станом «не мігровано».
#. [PoC] **Given** картка, у полі «Зрізи» якої бракує наявного файлу зрізу **When** запускається перевірка вимог **Then** вона завершується помилкою про невідповідність переліку зрізів файлам.
#. [PoC] **Given** у релізі є зрізи з залежностями між собою **When** генерується файл релізу **Then** кожен зріз стоїть у хвилі після всіх зрізів цього релізу, від яких він залежить, а залежності від раніших релізів вважаються виконаними.
#. [PoC] **Given** PR змінює файл вимоги **When** його переглядають **Then** тіло PR містить рішення власника, яке зміна реалізує; без нього PR не зливається. Перевіряється на рев'ю, не автоматично.

**Граничні випадки**
- [PoC] Вимога без релізу (картка екранів, карта досвіду) не має зрізів; на неї посилаються ідентифікатором вимоги.
- [PoC] Екран у карті екранів має реліз MVP, а використовується вже в PoC — його вказують у «Дизайн» зрізу PoC; покриття рахує екран покритим зрізом свого або ранішого релізу.
- [PoC] Назву борда канваса перевірка лише розпізнає за формою, бо реєстру бордів у репозиторії немає.
