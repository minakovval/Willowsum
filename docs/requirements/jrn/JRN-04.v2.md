# JRN-04@v2 · Клієнт радника

**Реліз:** v2

**Зв'язки**
- Розширює: —
- Залежить від: FLW-31@v2, FLW-32@v2, FLW-33@v2
- Дизайн: S-040, S-076, S-079, S-157, S-250, S-251, S-252, S-257, S-258
- Спільні правила: П-6, П-17, SCR-02
- Сценарії: UC-ADV-07, UC-ADV-10, UC-ADV-11, UC-ADV-12, UC-ADV-15, UC-ADV-16, UC-ADV-17, UC-ADV-23, UC-ADV-24, UC-ADV-26, UC-ADV-28, UC-RPT-15, UC-RPT-17, UC-SUB-18, UC-SUB-19, UC-SUB-20
- Модуль: advisor
- Перевіряється: —

**Персони.** Клієнтка — Софія, 60 років, не любить цифр і довіряє раднику. Радник — Тарас, незалежна консалтингова фірма, веде 80 родин.

**Мета.** Софії — зрозуміла картина без зусиль і контроль над тим, що бачить радник. Тарасу — актуальні дані без ручного збору і готові звіти до зустрічей.

| Етап | Мета користувача | Що повинен забезпечити продукт |
| --- | --- | --- |
| 1. Пропозиція | Софія не хоче нічого вводити | Радник готує простір заздалегідь |
| 2. Підготовка радником | Наповнити простір за годину | Фіди з систем радника, черга незіставлених рахунків, імпорт |
| 3. Передача клієнтці | Прийняти вже заповнений простір | Рекомендовані налаштування доступу; зрозумілий екран «Надати доступ раднику» |
| 4. Регулярне використання | Раз на місяць переконатися, що все гаразд | Простий вигляд Головної і підсумок простою мовою |
| 5. Підготовка до зустрічі | Мати актуальні дані | Попередження про застарілі дані перед формуванням брендованого звіту |
| 6. Зміни в житті | Знати, хто що змінив | Позначка «змінено радником», історія поля, кнопка «Повернути» |
| 7. Зміна радника | Зберегти свої дані | Відкликання за 60 с; 30 днів на вибір власного плану; дані не втрачаються |

**Моменти, що повинні спрацювати**

- Клієнтка входить у вже заповнений простір і бачить net worth у першу хвилину.
- Жодна правка радника не залишається непомітною для клієнтки.
- Відкликання доступу діє для всієї організації радника одразу.

**Цільові показники**

- Не менше 60 % запрошених радником клієнтів активують простір протягом 30 днів.
- Підготовка звіту до зустрічі займає не більше 10 хв.
- Повнота даних клієнтів радників-пілотів — не менше 80 % через 3 місяці.

**Гіпотези для перевірки**

- Радники — ефективний канал для клієнтів, які самі продукт не шукали б.
- Клієнтам радників потрібні спрощений вигляд і чіткий контроль доступу, а не повний функціонал.
- Радник платитиме за клієнтів, якщо фіди працюють без ручної роботи.
