**Мета.** Як команда розробки, ми хочемо мати відтворювані середовища, автоматичні перевірки кожної зміни і контрольований випуск, щоб часто випускати зміни без регресій.

**Функціональні вимоги**
1. Є два постійні середовища: dev і production, а також тимчасове середовище форми production для тестів; staging у цьому релізі немає. Інфраструктура кожного описана кодом і відтворюється автоматично.
2. Кожне злиття в основну гілку проходить юніт-, інтеграційні та E2E-тести, перевірку типів, лінтер, сканування безпеки і перевірку неперекладених рядків.
3. Покриття бізнес-логіки тестами — не менше 80 %.
4. Пряма зміна основної гілки заборонена: лише через pull request з рев'ю іншим виконавцем. Зміни в автентифікації, правах доступу, шифруванні, грошових розрахунках і моделі даних додатково рецензує відповідальний за безпеку чи архітектуру.
5. Злиття в основну гілку не розгортає жодного середовища автоматично; нові функції приховані прапорцями функцій.
6. Випуск у production — лише з дозволу власника продукту.
7. Незавершені функції приховані прапорцями. У production немає екранів чи віджетів «Скоро буде» (Coming soon).
8. Функція доступна користувачеві лише тоді, коли ввімкнені і прапорець функції, і план. Нова функція за замовчуванням вимкнена в усіх планах; ключ функції незмінний; функцію не можна видалити, лише архівувати.
9. Частота релізів: веб — щотижня.
10. Дії CI посилаються на зовнішні дії за незмінним хешем коміту, а не за змінним тегом.

**Бізнес-правила**
- Типи керування функцією: увімкнено чи вимкнено, ліміт кількості, ліміт на період, глибина історії в місяцях, обсяг у гігабайтах.

**Критерії приймання**

| Критерій | Поріг | Спосіб перевірки |
| --- | --- | --- |
| Середовища | dev, production і тимчасове середовище форми production описані кодом | Відтворення тимчасового середовища форми production з нуля ≤ 1 год |
| CI/CD | Кожне злиття проходить усі тести і перевірки; покриття бізнес-логіки ≥ 80 % | Звіт CI |
| Прапорці функцій | 0 екранів «Скоро буде» в production; незавершені функції приховані | Огляд релізу |
| Частота релізів | Веб — щотижня | Метрики DORA |
| Захист гілки | 0 прямих комітів в основну гілку | Аудит історії гілки |

1. **Given** pull request змінює правила доступу **When** його відкривають **Then** злиття можливе лише після рев'ю іншим виконавцем і рецензентом з безпеки.
2. **Given** функція позначена прапорцем як вимкнена **When** користувач будь-якого плану відкриває застосунок **Then** функція не показується і її API недоступний.

Припущення: поки є лише одне серверне середовище, «опис кодом» допускається у вигляді файлів конфігурації контейнерів і скриптів розгортання; повноцінний інструмент опису інфраструктури додається з другим середовищем.
