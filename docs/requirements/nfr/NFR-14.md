**Функціональні вимоги**
#. [PoC] Кожна відповідь API містить заголовки з таблиці «Заголовки API». Маршрут може задати власне значення заголовка (наприклад, суворішу політику вмісту для файлів), і воно має пріоритет.
#. [PoC] Вебзастосунок і адмін-панель на всіх шляхах надсилають: HSTS, X-Content-Type-Options: nosniff, Referrer-Policy: strict-origin-when-cross-origin, закриту Permissions-Policy, Cross-Origin-Opener-Policy: same-origin, X-Frame-Options: DENY.
#. [PoC] Статичні файли вебзастосунку й адмін-панелі надсилають політику вмісту (CSP) з таблиці «Політика вмісту вебу». Ця політика не застосовується до відповідей API.
#. [PoC] HTML-оболонка застосунку має Cache-Control: no-cache; статичні ресурси з хешем у назві — immutable.
#. [PoC] Обмеження частоти запитів діють за IP-адресою клієнта у фіксованих вікнах по 1 хв: публічні ендпоінти (публічні дії без входу, підписані посилання на файли, вебхуки) — 60 на хвилину; завантаження файлів — 30 на хвилину; решта API і API адмін-панелі — 600 на хвилину.
#. [PoC] Перевищення ліміту повертає 429 з кодом RATE_LIMITED і заголовком Retry-After.
#. [лише PoC] Ендпоінти автентифікації мають власні ліміти: 5 невдалих входів за 15 хв на акаунт і ліміт помилкових входів з однієї IP-адреси на годину, реєстрація — 5 на годину з однієї IP-адреси; невірні паролі в step-up рахуються в тому самому ліміті, що й невдалі входи, і після нього сесія завершується; надсилання токена банківського провайдера — не більше 5 спроб за 15 хв на акаунт.
#. [MVP] Ендпоінти автентифікації мають власні ліміти: 5 невдалих входів за 15 хв на акаунт і ліміт помилкових входів з однієї IP-адреси на годину, реєстрація — 5 на годину з однієї IP-адреси; надсилання кодів step-up — не більше 5 на годину на акаунт, 5 невірних кодів за 15 хв блокують step-up на 15 хв; надсилання токена банківського провайдера — не більше 5 спроб за 15 хв на акаунт.
#. [PoC] IP-адреса клієнта визначається лише з довірених проксі; кількість довірених проміжних вузлів налаштовується (за замовчуванням 0), а заголовок X-Forwarded-For від клієнта не приймається без довіреного проксі.
#. [лише PoC] Обмеження частоти увімкнені за замовчуванням у production і в кожному іншому розгорнутому середовищі. Їх можна вимкнути налаштуванням лише для навантажувального тесту.
#. [MVP] Обмеження частоти увімкнені за замовчуванням у staging і production. Їх можна вимкнути налаштуванням лише для навантажувального тесту.
#. [PoC] Якщо працює більше одного екземпляра API, лічильники обмежень зберігаються у спільному сховищі, а не в пам'яті процесу.
#. [MVP] Джерела Google Maps додаються до політики вмісту лише разом з увімкненням мапи портфеля, після тижня перевірки в режимі Content-Security-Policy-Report-Only у staging; шаблони звужуються до фактично використаних хостів.
#. [MVP] Серверний ключ карт обмежений IP-адресою сервера і API геокодування; ключ браузера обмежений HTTP-referrer домену застосунку і API карт та автодоповнення адрес, без геокодування. Для staging і production — окремі ключі (бажано окремі проєкти), з денними квотами і бюджетними сповіщеннями.

**Заголовки API**

| Заголовок | Значення | Примітка |
| --- | --- | --- |
| X-Content-Type-Options | nosniff | Усі відповіді |
| X-Frame-Options | DENY | SAMEORIGIN для файлів, які застосунок показує у вбудованому переглядачі на тому самому домені |
| Content-Security-Policy | default-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'none' | Підписані файли додатково мають sandbox |
| Referrer-Policy | no-referrer | Усі відповіді API |
| Cross-Origin-Resource-Policy | same-origin | Усі відповіді |
| Cache-Control | no-store для API, API адмін-панелі і автентифікації | Маршрут може задати власне значення (наприклад, private, max-age=300 для схем типів активів) |
| [лише PoC] Strict-Transport-Security | max-age=31536000; includeSubDomains | Лише розгорнуті середовища (HTTPS) |
| [MVP] Strict-Transport-Security | max-age=31536000; includeSubDomains | Лише staging і production |

**Критерії приймання**

| Критерій | Поріг | Спосіб перевірки |
| --- | --- | --- |
| Заголовки API | Усі заголовки з таблиці на 100 % відповідей | Автотести заголовків для типових і спеціальних маршрутів |
| [лише PoC] Заголовки вебу | CSP, HSTS, X-Frame-Options на всіх статичних шляхах; відсутність CSP вебу на відповідях API | Тест статичного сервера в CI і перевірка заголовків після розгортання |
| [MVP] Заголовки вебу | CSP, HSTS, X-Frame-Options на всіх статичних шляхах; відсутність CSP вебу на відповідях API | Автотест на розгорнутому staging |
| Обмеження частоти | 61-й публічний запит за хвилину отримує 429 з Retry-After | Автотести обмежень |
| CSP без небезпечних джерел | 0 джерел http:; без 'unsafe-eval' | Автоматична перевірка політики в CI |
| [MVP] Ключі карт | Обмеження referrer, IP і API; окремі ключі на середовище | Ручна перевірка консолі провайдера перед увімкненням мапи |

#. [PoC] **Given** клієнт надсилає 61 запит до публічного ендпоінта за одну хвилину **When** надходить 61-й запит **Then** API відповідає 429 з кодом RATE_LIMITED і заголовком Retry-After.
#. [PoC] **Given** відповідь API з фінансовими даними **When** браузер її отримує **Then** відповідь має Cache-Control: no-store і не може бути вбудована у фрейм.
#. [PoC] **Given** сторінку вебзастосунку намагаються вбудувати у фрейм на сторонньому сайті **When** браузер завантажує фрейм **Then** вбудовування заблоковано.
#. [MVP] **Given** мапа портфеля вимкнена **When** перевіряється політика вмісту **Then** у ній немає жодного джерела Google.

**Граничні випадки**
- [лише PoC] У PoC банківські інтеграції лише серверні; перехід до банку — навігацією верхнього рівня; CSP не змінюється.
- [MVP] Банківський провайдер потребує власних джерел у script-src, connect-src і frame-src: вони додаються лише разом з увімкненням інтеграції.
- [MVP] Referrer-Policy вебу не може бути no-referrer, бо обмеження ключа браузера за referrer потребує домену в заголовку Referer.

Припущення: домен CAPTCHA відповідає обраному постачальнику CAPTCHA (Cloudflare); інший постачальник змінює лише це джерело.
