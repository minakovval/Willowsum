# NFR-19 · Критерії готовності вимоги (Definition of Done)

**Реліз:** PoC (перевірки лише в десктопному браузері від 1280 px, без повної перевірки WCAG 2.2 AA і статей довідки); PoC v2 (стаття довідки для функції, видимої користувачу; метрики якості поставки); MVP (ролі й учасники простору; три діапазони ширини, WCAG 2.2 AA, переклад uk і en) · **Пріоритет:** M

**Зв'язки**
- Зрізи: NFR-19@PoC, NFR-19@PoC v2, NFR-19@MVP
- Модуль: —

**Мета.** Як власник продукту, я хочу мати однаковий для будь-якої команди перелік умов, за яких вимога вважається завершеною, щоб кожна функція виходила протестованою, безпечною, доступною і задокументованою.

**Мета.** Як власник продукту, я хочу мати однаковий для будь-якої команди перелік умов, за яких вимога вважається завершеною, щоб кожна функція виходила протестованою, безпечною, доступною і задокументованою.

**Функціональні вимоги**
#. [PoC] Роботу над функцією починають лише із задачі, що називає конкретну вимогу.
#. [PoC] Автоматичні тести пишуться до реалізації: щонайменше один тест на кожен критерій приймання і на кожен граничний випадок. Спочатку тести падають.
#. [PoC] Тест приймання змінюється лише разом зі зміною вимоги, яку погодив власник продукту.
#. [PoC] Pull request має в назві ідентифікатор вимоги і перелік реалізованих бізнес-правил в описі. Рецензент — не автор. Зміни в автентифікації, правах доступу, шифруванні, грошових розрахунках і моделі даних додатково рецензує відповідальний за безпеку чи архітектуру.
#. [PoC] Неоднозначність або суперечність між вимогами виконавець не вирішує сам: задача зупиняється, питання передається власнику продукту.
#. [PoC] Нова залежність або зовнішній сервіс вимагає записаного обґрунтування.
#. [PoC–PoC v2] Після злиття функція потрапляє в production лише з дозволу власника продукту і за прапорцем функції.
#. [MVP] Після злиття функція розгортається в staging за прапорцем функції; у production — лише з дозволу власника продукту.

**Критерії приймання**

| Критерій | Поріг | Спосіб перевірки |
| --- | --- | --- |
| Тести | 100 % критеріїв приймання і граничних випадків покриті автотестами; усі зелені в CI | Звіт CI; відповідність тестів переліку критеріїв |
| [PoC–PoC v2] Платформи | Тести проходять у десктопному браузері від 1280 px | Звіт E2E-тестів |
| [MVP] Платформи | Тести проходять у вебі в трьох діапазонах ширини (< 600 px, 600–1279 px, ≥ 1280 px); у мобільному клієнті — з релізу v1-mobile | Звіт E2E-тестів |
| Бізнес-правила | Усі правила, що стосуються вимоги, дотримано | Тести; рев'ю |
| Каталог функцій | Функція має незмінний ключ у каталозі функцій і перевірку доступності за планом; 0 жорстко зашитих лімітів чи назв планів | Код-рев'ю; автоматичний пошук у CI |
| Аудит і права | Кожна зміна даних пише запис у журнал аудиту; тести прав для кожної ролі, включно з обмеженим доступом | Автотести аудиту і прав |
| [PoC–PoC v2] Ізоляція | Кожен запит обмежений простором і правами користувача; користувач не дізнається про записи поза доступом | Автотест-обхід маршрутів |
| [MVP] Ізоляція | Кожен запит обмежений простором, роллю і областю доступу; учасник не дізнається про записи поза доступом | Автотест-обхід маршрутів |
| Гроші | Лише Decimal; суми в оригінальній валюті; конвертація за датованим курсом; округлення лише при показі | Статичний аналіз; юніт-тести |
| Стани інтерфейсу | Порожній стан, завантаження і помилка для кожного екрана і віджета; 0 «Скоро буде» | Візуальні і E2E-тести |
| [PoC–PoC v2] Мова | Усі рядки через ключі перекладу | Lint i18n |
| [MVP] Доступність і мова | WCAG 2.2 AA; усі рядки через ключі перекладу | Автоматична перевірка доступності; lint i18n |
| Безпека | 0 нових зауважень High і Critical від сканування безпеки | Звіти SAST, SCA, сканування секретів |
| Приватність | 0 персональних даних у логах, аналітиці і звітах про помилки; робота лише з синтетичними даними | Сканер логів; рев'ю |
| [лише PoC] Документація | Документацію API оновлено | Рев'ю pull request |
| [PoC v2] Документація | Документацію API і статтю довідки оновлено, якщо функція видима користувачу | Рев'ю pull request |

[PoC v2]
#. [PoC] **Given** вимога має 6 критеріїв приймання і 3 граничні випадки **When** pull request подано на рев'ю **Then** у ньому щонайменше 9 автотестів, кожен прив'язаний до критерію чи граничного випадку.
#. [PoC] **Given** pull request змінює правила доступу **When** його переглянув лише автор **Then** злиття неможливе.
#. [лише PoC] **Given** функція видима користувачу **When** вона позначається завершеною **Then** існують порожній стан, стан завантаження і стан помилки, а тексти взято з ключів перекладу.
#. [лише PoC v2] **Given** функція видима користувачу **When** вона позначається завершеною **Then** існують порожній стан, стан завантаження і стан помилки, тексти взято з ключів перекладу, і є стаття довідки.
#. [MVP] **Given** функція видима користувачу **When** вона позначається завершеною **Then** існують порожній стан, стан завантаження і стан помилки, тексти перекладено uk і en, і є стаття довідки.
#. [PoC] **Given** сканер безпеки знайшов нове зауваження High **When** перевіряється готовність вимоги **Then** вимога не вважається завершеною до виправлення.

**Граничні випадки**
- [PoC] Функція без інтерфейсу (фонова задача, API): вимоги до станів інтерфейсу і доступності не застосовуються; решта критеріїв діють.

Припущення: виняток для функцій без інтерфейсу додано як розумне значення.
