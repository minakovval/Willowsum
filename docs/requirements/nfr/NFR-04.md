# NFR-04 · Продуктивність

**Реліз:** PoC v2 (базові ліміти швидкодії списків та імпорту, цілі запитів API); MVP (Головна, пошук, Core Web Vitals, конкурентне редагування, перерахунок net worth, повільні віджети); v1-mobile (холодний старт і плавність мобільного застосунку) · **Пріоритет:** M

**Зв'язки**
- Зрізи: NFR-04@PoC v2, NFR-04@MVP, NFR-04@v1-mobile
- Модуль: —

**Мета.** Як користувач із великою історією, я хочу, щоб Головна і списки відкривалися швидко навіть на великому просторі, щоб продуктом було зручно користуватися щодня.

**Релізні зрізи.** Кожен зріз повний для свого релізу: функціональні вимоги, правила, права, стани і критерії приймання, що діють у ньому, без посилань на інші зрізи. Зріз діє до релізу наступного зрізу.

| Реліз | Зріз | Що змінюється порівняно з попереднім зрізом |
| --- | --- | --- |
| PoC v2 | [NFR-04.poc-v2.md](NFR-04.poc-v2.md) | Запити API: читання ≤ 300 мс, запис ≤ 500 мс (p95); серверна пагінація; сторінка 50 транзакцій із фільтрами ≤ 500 мс (p95); цілі часу імпорту файлів; звіт вимірювань |
| MVP | [NFR-04.mvp.md](NFR-04.mvp.md) | Головна ≤ 2 с, пошук, Core Web Vitals, оптимістичне блокування, перерахунок net worth ≤ 5 хв, повільні віджети окремо |
| v1-mobile | [NFR-04.v1-mobile.md](NFR-04.v1-mobile.md) | Холодний старт мобільного застосунку ≤ 2,5 с і 60 кадрів за секунду |

**Рішення ведучого (2026-11-12, без схвалення власника):** зріз перенесено з PoC у PoC v2: у родини власника кілька тисяч транзакцій на рік, а навантажувальний тест потребує тимчасового середовища форми production.
