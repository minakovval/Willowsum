**Мета.** Як команда розробки, ми хочемо мати відтворювані середовища, автоматичні перевірки кожної зміни і контрольований випуск, щоб часто випускати зміни без регресій.

**Функціональні вимоги**
#. [лише PoC] Є локальне середовище, CI і production, а також тимчасове середовище перевірки відновлення (частина production) лише для щотижневої перевірки відновлення резервної копії; staging у цьому релізі немає; решта перевірок іде в CI. Інфраструктура кожного описана кодом і відтворюється автоматично.
#. [лише PoC v2] Є два постійні середовища: dev і production, а також тимчасове середовище форми production для тестів; staging у цьому релізі немає. Інфраструктура кожного описана кодом і відтворюється автоматично.
#. [PoC–PoC v2] Кожне злиття в основну гілку проходить юніт-, інтеграційні та E2E-тести, перевірку типів, лінтер, сканування безпеки і перевірку неперекладених рядків.
#. [MVP] Є три середовища: dev, staging і production. Інфраструктура кожного описана кодом і відтворюється автоматично.
#. [MVP] Кожне злиття в основну гілку проходить юніт-, інтеграційні та E2E-тести, перевірку типів, лінтер, сканування безпеки, перевірку доступності і неперекладених рядків.
#. [PoC] Покриття бізнес-логіки тестами — не менше 80 %.
#. [PoC] Пряма зміна основної гілки заборонена: лише через pull request з рев'ю іншим виконавцем. Зміни в автентифікації, правах доступу, шифруванні, грошових розрахунках і моделі даних додатково рецензує відповідальний за безпеку чи архітектуру.
#. [PoC–PoC v2] Злиття в основну гілку не розгортає жодного середовища автоматично; нові функції приховані прапорцями функцій.
#. [MVP] Злиття в основну гілку автоматично розгортає staging; нові функції приховані прапорцями функцій.
#. [PoC] Випуск у production — лише з дозволу власника продукту.
#. [PoC] Незавершені функції приховані прапорцями. У production немає екранів чи віджетів «Скоро буде» (Coming soon).
#. [лише PoC] Функція доступна користувачеві, коли ввімкнений її прапорець функції; перевірка плану в цьому релізі — заглушка «усе ввімкнено» (механізм прав плану закладено в архітектуру). Ключ функції незмінний; функцію не можна видалити, лише архівувати. Правило «нова функція вимкнена в усіх планах» і типи керування функцією за планом — з PoC v2 (рішення ведучого 2026-11-12).
#. [лише PoC] Релізи — за рішенням власника; щотижнева частота релізів вебу і метрики DORA — з PoC v2 (рішення ведучого 2026-11-12).
#. [PoC v2] Функція доступна користувачеві лише тоді, коли ввімкнені і прапорець функції, і план. Нова функція за замовчуванням вимкнена в усіх планах; ключ функції незмінний; функцію не можна видалити, лише архівувати.
#. [PoC v2–MVP] Частота релізів: веб — щотижня.
#. [v1-mobile] Частота релізів: веб — щотижня; мобільний застосунок — раз на 2 тижні плюс OTA-оновлення JavaScript-частини.
#. [PoC] Дії CI посилаються на зовнішні дії за незмінним хешем коміту, а не за змінним тегом.

[PoC v2] **Бізнес-правила**
- [PoC v2] Типи керування функцією: увімкнено чи вимкнено, ліміт кількості, ліміт на період, глибина історії в місяцях, обсяг у гігабайтах.

**Критерії приймання**

| Критерій | Поріг | Спосіб перевірки |
| --- | --- | --- |
| [лише PoC] Середовища | Локальне середовище, production і тимчасове середовище перевірки відновлення описані кодом | Відтворення тимчасового середовища перевірки відновлення з нуля ≤ 1 год |
| [лише PoC v2] Середовища | dev, production і тимчасове середовище форми production описані кодом | Відтворення тимчасового середовища форми production з нуля ≤ 1 год |
| [MVP] Середовища | dev, staging, production описані кодом | Відтворення staging з нуля ≤ 1 год |
| CI/CD | Кожне злиття проходить усі тести і перевірки; покриття бізнес-логіки ≥ 80 % | Звіт CI |
| Прапорці функцій | 0 екранів «Скоро буде» в production; незавершені функції приховані | Огляд релізу |
| [PoC v2–MVP] Частота релізів | Веб — щотижня | Метрики DORA |
| [v1-mobile] Частота релізів | Веб — щотижня; мобільний — раз на 2 тижні + OTA | Метрики DORA |
| Захист гілки | 0 прямих комітів в основну гілку | Аудит історії гілки |

#. [PoC] **Given** pull request змінює правила доступу **When** його відкривають **Then** злиття можливе лише після рев'ю іншим виконавцем і рецензентом з безпеки.
#. [PoC] **Given** функція позначена прапорцем як вимкнена **When** користувач будь-якого плану відкриває застосунок **Then** функція не показується і її API недоступний.

Припущення: поки є лише одне серверне середовище, «опис кодом» допускається у вигляді файлів конфігурації контейнерів і скриптів розгортання; повноцінний інструмент опису інфраструктури додається з другим середовищем.
