**Мета.** Як користувач, я хочу, щоб браузер не міг кешувати чи вбудовувати мої фінансові дані на сторонніх сайтах і щоб сервіс не можна було перевантажити запитами, щоб мої дані не витекли через атаки на клієнтську частину.

**Функціональні вимоги**
1. Кожна відповідь API містить заголовки з таблиці «Заголовки API». Маршрут може задати власне значення заголовка (наприклад, суворішу політику вмісту для файлів), і воно має пріоритет.
2. Вебзастосунок і адмін-панель на всіх шляхах надсилають: HSTS, X-Content-Type-Options: nosniff, Referrer-Policy: strict-origin-when-cross-origin, закриту Permissions-Policy, Cross-Origin-Opener-Policy: same-origin, X-Frame-Options: DENY.
3. Статичні файли вебзастосунку й адмін-панелі надсилають політику вмісту (CSP) з таблиці «Політика вмісту вебу». Ця політика не застосовується до відповідей API.
4. HTML-оболонка застосунку має Cache-Control: no-cache; статичні ресурси з хешем у назві — immutable.
5. Обмеження частоти запитів діють за IP-адресою клієнта у фіксованих вікнах по 1 хв: публічні ендпоінти (публічні дії без входу, підписані посилання на файли, вебхуки) — 60 на хвилину; завантаження файлів — 30 на хвилину; решта API і API адмін-панелі — 600 на хвилину.
6. Перевищення ліміту повертає 429 з кодом RATE_LIMITED і заголовком Retry-After.
7. Ендпоінти автентифікації мають власні ліміти: 5 невдалих входів за 15 хв на акаунт, реєстрація — 5 на годину з однієї IP-адреси; невірні паролі в step-up рахуються в тому самому ліміті, що й невдалі входи, і після нього сесія завершується; надсилання токена банківського провайдера — не більше 5 спроб за 15 хв на акаунт.
8. IP-адреса клієнта визначається лише з довірених проксі; кількість довірених проміжних вузлів налаштовується (за замовчуванням 0), а заголовок X-Forwarded-For від клієнта не приймається без довіреного проксі.
9. Обмеження частоти увімкнені за замовчуванням у staging і production. Їх можна вимкнути налаштуванням лише для навантажувального тесту.
10. Якщо працює більше одного екземпляра API, лічильники обмежень зберігаються у спільному сховищі, а не в пам'яті процесу.

**Заголовки API**

| Заголовок | Значення | Примітка |
| --- | --- | --- |
| X-Content-Type-Options | nosniff | Усі відповіді |
| X-Frame-Options | DENY | SAMEORIGIN для файлів, які застосунок показує у вбудованому переглядачі на тому самому домені |
| Content-Security-Policy | default-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'none' | Підписані файли додатково мають sandbox |
| Referrer-Policy | no-referrer | Усі відповіді API |
| Cross-Origin-Resource-Policy | same-origin | Усі відповіді |
| Cache-Control | no-store для API, API адмін-панелі і автентифікації | Маршрут може задати власне значення (наприклад, private, max-age=300 для схем типів активів) |
| Strict-Transport-Security | max-age=31536000; includeSubDomains | Лише staging і production |

**Політика вмісту вебу**

| Директива | Значення |
| --- | --- |
| default-src | 'self' |
| script-src | 'self' і домен CAPTCHA (challenges.cloudflare.com) |
| style-src | 'self' 'unsafe-inline' |
| img-src | 'self' data: blob: |
| font-src | 'self' data: |
| connect-src | 'self' |
| frame-src | домен CAPTCHA (challenges.cloudflare.com) |
| worker-src | 'self' blob: |
| object-src | 'none' |
| base-uri | 'self' |
| form-action | 'self' |
| frame-ancestors | 'none' |
| upgrade-insecure-requests | увімкнено |

**Критерії приймання**

| Критерій | Поріг | Спосіб перевірки |
| --- | --- | --- |
| Заголовки API | Усі заголовки з таблиці на 100 % відповідей | Автотести заголовків для типових і спеціальних маршрутів |
| Заголовки вебу | CSP, HSTS, X-Frame-Options на всіх статичних шляхах; відсутність CSP вебу на відповідях API | Автотест на розгорнутому staging |
| Обмеження частоти | 61-й публічний запит за хвилину отримує 429 з Retry-After | Автотести обмежень |
| CSP без небезпечних джерел | 0 джерел http:; без 'unsafe-eval' | Автоматична перевірка політики в CI |

1. **Given** клієнт надсилає 61 запит до публічного ендпоінта за одну хвилину **When** надходить 61-й запит **Then** API відповідає 429 з кодом RATE_LIMITED і заголовком Retry-After.
2. **Given** відповідь API з фінансовими даними **When** браузер її отримує **Then** відповідь має Cache-Control: no-store і не може бути вбудована у фрейм.
3. **Given** сторінку вебзастосунку намагаються вбудувати у фрейм на сторонньому сайті **When** браузер завантажує фрейм **Then** вбудовування заблоковано.

**Граничні випадки**
- У PoC банківські інтеграції лише серверні; перехід до банку — навігацією верхнього рівня; CSP не змінюється.

Припущення: домен CAPTCHA відповідає обраному постачальнику CAPTCHA (Cloudflare); інший постачальник змінює лише це джерело.
