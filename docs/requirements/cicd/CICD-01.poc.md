# CICD-01@PoC · Гілки, PR і захист основної гілки

**Реліз:** PoC · **Пріоритет:** M

**Зв'язки**
- Розширює: —
- Залежить від: —
- Дизайн: —
- Спільні правила: П-24, NFR-11, NFR-19
- Сценарії: —
- Модуль: —
- Перевіряється: —

1. Одна основна гілка main; робочі гілки живуть не довше 3 днів. Незавершена функція зливається вимкненою прапорцем.
2. Зміна потрапляє в main лише через PR. Назва PR починається з ID вимоги; опис перелічує критерії приймання і тести, що їх покривають.
3. Оскільки безкоштовний план GitHub не дозволяє технічно заборонити прямий запис у main, захист забезпечується так:
   - агенти працюють у робочих гілках; PR зливає агент-автор лише після зеленого CI на останньому коміті і вердикту «Ready» від рев'ю в іншій сесії агента; PR, що змінює зміст вимог, правила агентів або skills, агент зливає лише якщо в описі PR зафіксовано рішення власника, яке ця зміна реалізує; коментар власника «stop» або запитання власника в PR зупиняє злиття до відповіді власника; PR, що діє на хмару чи production — застосовує інфраструктуру, розгортає чи випускає реліз у production або змінює робочі процеси, які це роблять, налаштування довіри до них (OIDC, сховище секретів production) чи DNS production, — агент зливає лише після коментаря власника зі схваленням у цьому PR, написаного з облікового запису власника; код інфраструктури без застосування, перевірки CI і локальне середовище такого коментаря не потребують;
   - у production може потрапити лише образ, зібраний конвеєром з коміту, що пройшов усі перевірки і належить злитому PR;
   - щодня автоматична перевірка шукає коміти в main без злитого PR або з force-push і надсилає алерт власнику.

4. Чутливі зміни (автентифікація, права, шифрування, грошові розрахунки, схема БД, конвеєр і інфраструктура) отримують позначку автоматично за шляхами файлів і потребують окремого рев'ю безпеки в іншій сесії агента; без його вердикту «Ready» PR не зливається.
5. Рев'ю кожного PR робить інший агент, ніж автор.
