# CICD-07@PoC · Інфраструктура як код і резервні копії

**Реліз:** PoC · **Пріоритет:** M

**Зв'язки**
- Розширює: —
- Залежить від: CICD-04@PoC
- Дизайн: —
- Спільні правила: ARC-03, ARC-08, NFR-16
- Сценарії: —
- Модуль: —
- Перевіряється: tools/infra-check/test/start.test.mjs

1. Уся інфраструктура (ВМ, мережа, DNS, сховища, доступи) описана кодом у репозиторії і змінюється лише через PR із планом змін у описі. Ручні зміни виявляє щоденна перевірка розбіжностей.
2. Резервування: безперервне архівування журналу записів БД (сегмент закривається щонайменше раз на 5 хв), щоденна базова копія БД і файлів, шифрування перед відправкою, зберігання в іншому регіоні ЄС і в іншому обліковому записі з окремими правами, термін 35 днів.
3. Раз на тиждень конвеєр автоматично відновлює останню копію в тимчасове середовище, перевіряє цілісність журналу проводок і кількість записів, фіксує фактичні RPO і RTO та знищує середовище. Раз на квартал — повна репетиція відновлення за ранбуком.
4. У цьому релізі розгорнуте середовище одне — production; інфраструктура staging не застосовується.
5. Разом із розгортанням production будується перевірка «живий»: запланований робочий процес GitHub Actions кожні 5–10 хв звертається до перевірки готовності API production (`/health/ready`); коли перевірка не проходить, він відкриває в репозиторії задачу або оновлює вже відкриту, і GitHub надсилає власнику продукту лист; коли перевірка знову проходить, задача закривається.
6. Алерт цього розділу — задача в репозиторії, про яку GitHub надсилає власнику продукту лист; окремого сервісу моніторингу немає.

| Критерій | Поріг | Перевірка |
| --- | --- | --- |
| Вік останнього заархівованого сегмента журналу | ≤ 15 хв, інакше алерт власнику | Перевірка кожні 10 хв |
| Успішне автоматичне відновлення | Щотижня; невдача — алерт власнику | Журнал конвеєра |
| Перевірка «живий» | Кожні 5–10 хв; недоступність production → лист власнику після першої невдалої перевірки | Пробний запуск на недоступній адресі під час налаштування |
