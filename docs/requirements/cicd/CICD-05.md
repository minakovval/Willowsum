#. [MVP] Розгортання запускається вручну для конкретного образу, що вже працює на staging. Конвеєр перевіряє, що запуск ініціював власник, і вимагає ввести перші 7 символів хешу коміту для підтвердження.
#. [MVP] Перед розгортанням створюється точка відновлення БД; міграції виконуються окремим кроком до заміни коду.
#. [MVP] Нова версія піднімається поруч ізі старою; трафік перемикається після успішної перевірки «готовий». Простою немає.
#. [MVP] Після перемикання автоматичні smoke-тести перевіряють вхід, Головну, створення запису в тестовому просторі та фонову задачу. Якщо тести або частка помилок 5xx за 10 хв виходять за поріг, трафік автоматично повертається на попередню версію.
#. [MVP] Відкат коду завжди можливий без відкату схеми БД, бо міграції сумісні з попередньою версією коду.
#. [MVP] Кожне розгортання записується в журнал релізів: версія, час, хто схвалив, список PR і ID вимог, результат smoke-тестів.
