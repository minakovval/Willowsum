# CICD-05 · Розгортання в production і відкат

**Реліз:** PoC · **Пріоритет:** M

1. Розгортання запускається вручну для конкретного образу, що вже працює на staging. Конвеєр перевіряє, що запуск ініціював власник, і вимагає ввести перші 7 символів хешу коміту для підтвердження.
2. Перед розгортанням створюється точка відновлення БД; міграції виконуються окремим кроком до заміни коду.
3. Нова версія піднімається поруч ізі старою; трафік перемикається після успішної перевірки «готовий». Простою немає.
4. Після перемикання автоматичні smoke-тести перевіряють вхід, Головну, створення запису в тестовому просторі та фонову задачу. Якщо тести або частка помилок 5xx за 10 хв виходять за поріг, трафік автоматично повертається на попередню версію.
5. Відкат коду завжди можливий без відкату схеми БД, бо міграції сумісні з попередньою версією коду.
6. Кожне розгортання записується в журнал релізів: версія, час, хто схвалив, список PR і ID вимог, результат smoke-тестів.

| Критерій | Поріг | Перевірка |
| --- | --- | --- |
| Простій під час розгортання | 0 втрачених запитів | Навантажувальний тест під час розгортання на staging |
| Час відкату на попередню версію | ≤ 5 хв | Щомісячна репетиція на staging |
| Розгортання в production без схвалення власника | 0 | Журнал релізів |
