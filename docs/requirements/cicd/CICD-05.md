**Реліз:** PoC (smoke-тести без Головної); PoC v2 (розгортання без простою, автовідкат, репетиції); MVP (smoke-тест Головної) · **Пріоритет:** M

**Зв'язки**
- Зрізи: CICD-05@PoC, CICD-05@PoC v2, CICD-05@MVP
- Модуль: —

**Релізні зрізи.** Кожен зріз повний для свого релізу: функціональні вимоги, правила, права, стани і критерії приймання, що діють у ньому, без посилань на інші зрізи. Зріз діє до релізу наступного зрізу.

- [MVP] Спільні правила: ARC-02, ARC-03

- Перевіряється: —

#. [PoC–PoC v2] Розгортання запускається вручну для конкретного образу з main, що пройшов усі перевірки конвеєра. Конвеєр перевіряє, що запуск ініціював власник, і вимагає ввести перші 7 символів хешу коміту для підтвердження.
#. [MVP] Розгортання запускається вручну для конкретного образу, що вже працює на staging. Конвеєр перевіряє, що запуск ініціював власник, і вимагає ввести перші 7 символів хешу коміту для підтвердження.
#. [PoC] Перед розгортанням створюється точка відновлення БД; міграції виконуються окремим кроком до заміни коду.
#. [лише PoC] Нова версія замінює стару після успішної перевірки «готовий»; короткий простій допустимий. Розгортання поруч зі старою версією без простою — з PoC v2 (рішення ведучого 2026-11-12).
#. [лише PoC] Після заміни автоматичні smoke-тести перевіряють вхід, створення запису в тестовому просторі та фонову задачу. Якщо тести не проходять, розгортання позначається невдалим, а власник відкочує версію вручну. Автоматичний відкат за smoke-тестами і часткою помилок 5xx — з PoC v2 (рішення ведучого 2026-11-12).
#. [PoC v2] Нова версія піднімається поруч ізі старою; трафік перемикається після успішної перевірки «готовий». Простою немає.
#. [лише PoC v2] Після перемикання автоматичні smoke-тести перевіряють вхід, створення запису в тестовому просторі та фонову задачу. Якщо тести або частка помилок 5xx за 10 хв виходять за поріг, трафік автоматично повертається на попередню версію. Частку 5xx у цьому релізі рахує крок розгортання з рядків JSON журналу сервера нової версії (події запитів з кодом відповіді); метрик у зовнішньому сервісі немає.
#. [MVP] Після перемикання автоматичні smoke-тести перевіряють вхід, Головну, створення запису в тестовому просторі та фонову задачу. Якщо тести або частка помилок 5xx за 10 хв виходять за поріг, трафік автоматично повертається на попередню версію.
#. [PoC] Відкат коду завжди можливий без відкату схеми БД, бо міграції сумісні з попередньою версією коду.
#. [PoC] Кожне розгортання записується в журнал релізів: версія, час, хто схвалив, список PR і ID вимог, результат smoke-тестів.

| Критерій | Поріг | Перевірка |
| --- | --- | --- |
| [лише PoC] Відкат на попередню версію вручну | ≤ 5 хв, без відкату схеми БД | Перевірка під час першого розгортання в production |
| [лише PoC v2] Простій під час розгортання | 0 втрачених запитів | Навантажувальний тест під час розгортання на тимчасовому середовищі форми production |
| [лише PoC v2] Час відкату на попередню версію | ≤ 5 хв | Щомісячна репетиція на тимчасовому середовищі форми production |
| [MVP] Простій під час розгортання | 0 втрачених запитів | Навантажувальний тест під час розгортання на staging |
| [MVP] Час відкату на попередню версію | ≤ 5 хв | Щомісячна репетиція на staging |
| Розгортання в production без схвалення власника | 0 | Журнал релізів |
