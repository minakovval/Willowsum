# CICD-05@PoC · Розгортання в production і відкат

**Реліз:** PoC · **Пріоритет:** M

**Зв'язки**
- Розширює: —
- Залежить від: CICD-03@PoC, CICD-04@PoC
- Дизайн: —
- Спільні правила: П-26, ARC-02, ARC-03
- Сценарії: —
- Модуль: —
- Перевіряється: —

1. Розгортання запускається вручну для конкретного образу з main, що пройшов усі перевірки конвеєра. Конвеєр перевіряє, що запуск ініціював власник, і вимагає ввести перші 7 символів хешу коміту для підтвердження.
2. Перед розгортанням створюється точка відновлення БД; міграції виконуються окремим кроком до заміни коду.
3. Нова версія піднімається поруч ізі старою; трафік перемикається після успішної перевірки «готовий». Простою немає.
4. Після перемикання автоматичні smoke-тести перевіряють вхід, створення запису в тестовому просторі та фонову задачу. Якщо тести або частка помилок 5xx за 10 хв виходять за поріг, трафік автоматично повертається на попередню версію. Частку 5xx у цьому релізі рахує крок розгортання з рядків JSON журналу сервера нової версії (події запитів з кодом відповіді); метрик у зовнішньому сервісі немає.
5. Відкат коду завжди можливий без відкату схеми БД, бо міграції сумісні з попередньою версією коду.
6. Кожне розгортання записується в журнал релізів: версія, час, хто схвалив, список PR і ID вимог, результат smoke-тестів.

| Критерій | Поріг | Перевірка |
| --- | --- | --- |
| Простій під час розгортання | 0 втрачених запитів | Навантажувальний тест під час розгортання на тимчасовому середовищі форми production |
| Час відкату на попередню версію | ≤ 5 хв | Щомісячна репетиція на тимчасовому середовищі форми production |
| Розгортання в production без схвалення власника | 0 | Журнал релізів |
