# CICD-12 · Зберігання секретів і доступів

**Реліз:** MVP · **Пріоритет:** M

Секрети (ключі, паролі, токени) створюють і розносять машини, а не люди. Людина вводить лише кілька кореневих доступів один раз і ніколи — у чат, код, задачу чи документ.

**Де що зберігається**

| Що | Де | Хто створює |
| --- | --- | --- |
| Особисті паролі власника, коди відновлення, доступ до реєстратора домену і хмари | Менеджер паролів власника з другим фактором (passkey або TOTP) | Власник |
| Секрети застосунку (паролі БД, ключі сесій, головний ключ шифрування, ключі підпису) для кожного середовища | Сховище секретів (Bitwarden Secrets Manager, регіон ЄС) — окремий проєкт на кожне середовище | Конвеєр інфраструктури генерує випадкові значення і записує їх у сховище напряму |
| Ключі зовнішніх сервісів (платежі, пошта, CAPTCHA, курси валют) | Те саме сховище, проєкт середовища | Власник один раз створює ключ у кабінеті сервісу і вставляє його у вебформу сховища |
| Доступ конвеєра GitHub Actions до хмари | Без збережених ключів: короткоживучі токени через OIDC-довіру між GitHub і хмарою | Опис інфраструктури |
| Доступ конвеєра до сховища секретів | Один машинний токен на середовище в GitHub Actions secrets, з правом лише читати свій проєкт | Власник один раз |
| Секрети для сесій агентів (тестові ключі пісочниць провайдерів) | Налаштування середовища Claude (секрети середовища), лише значення для локального середовища і CI | Власник один раз |

**Функціональні вимоги**

1. Жоден секрет не зберігається в репозиторії, образах, логах, задачах, коментарях PR, документах і чатах з агентами. Агент ніколи не просить вставити секрет у чат; якщо секрету бракує, він називає змінну і місце, куди власник має її додати.
2. Внутрішні секрети застосунку генеруються автоматично описом інфраструктури (довжина ≥ 32 байти випадкових даних) і записуються в сховище без показу людині.
3. Застосунок під час старту отримує секрети зі сховища або з середовища запуску, яке наповнює конвеєр; конфігурація перевіряється схемою, і за відсутності секрету процес не стартує, називаючи змінну без значення.
4. Кожне середовище має окремі секрети. Секрети production недоступні агентам, CI для PR і staging.
5. Агенти отримують лише тестові ключі пісочниць через секрети середовища Claude; для production вони діють тільки через дозволені дії конвеєра після схвалення власника.
6. Ротація: внутрішні секрети — автоматично щонайменше раз на рік і негайно після підозри на витік, без простою; ключі зовнішніх сервісів — за нагадуванням власнику раз на рік. Кожна ротація записується в журнал.
7. Кожне читання секретів production машинним доступом записується в журнал сховища; доступ людей до значень production — лише власника, з другим фактором.
8. Якщо сканер секретів знаходить секрет у коді або історії, PR блокується, а знайдений секрет вважається скомпрометованим і ротується.
9. Перехід на профіль «Комерційний» замінює сховище на керований сервіс секретів хмари лише зміною адаптера і конфігурації; імена секретів не змінюються.

**Що робить власник один раз**

- Створює акаунт сховища секретів і проєкти на середовища, видає машинні токени.
- Додає токен сховища в GitHub Actions secrets і тестові ключі — у секрети середовища Claude.
- Створює ключі зовнішніх сервісів у їхніх кабінетах і вставляє у вебформу сховища.

Усе інше (паролі БД, ключі шифрування, ключі підпису) створюється і оновлюється автоматично.

| Критерій | Поріг | Перевірка |
| --- | --- | --- |
| Секрети в репозиторії, історії git, образах, логах | 0 | Сканер секретів на кожному PR і щотижня по всій історії |
| Секрет, згенерований людиною вручну для внутрішніх потреб застосунку | 0 | Рев'ю опису інфраструктури |
| Доступ агентів, CI для PR або staging до секретів production | Відсутній | Щоквартальний перегляд прав сховища |
| Старт процесу без обов'язкового секрету | Відмова з назвою змінної, без значення | Тест |
| Вік внутрішнього секрету production | ≤ 12 місяців | Щомісячна перевірка конвеєром |

Припущення: обрано Bitwarden Secrets Manager через безкоштовний тариф, регіон даних у ЄС, інтеграцію з GitHub Actions і можливість тримати там же особисті паролі власника; рівноцінна заміна — Infisical.
