# FLW-58@v2 · Перевірка особи через офіційний цифровий гаманець
> Згенеровано з [FLW-58.md](FLW-58.md) командою `node tools/req-check/index.mjs --views`. Не редагувати: змінюйте джерело.

**Реліз:** v2 · **Пріоритет:** C

**Зв'язки**
- Розширює: —
- Залежить від: VLT-20@v2, VLT-21@v2
- Дизайн: S-246
- Спільні правила: П-5, П-6, П-8, П-10, П-23, SCR-02
- Сценарії: UC-VLT-26, UC-VLT-28, UC-VLT-68, UC-VLT-69
- Модуль: vault-items
- Перевіряється: —

**Мета.** Як користувач або довірена особа, я хочу підтвердити особу через офіційний цифровий документ без зберігання самого credential у продукті.

**Актор і точка входу.** Користувач або довірена особа на кроці «Підтвердіть особу»: відновлення доступу до Сейфу, запит екстреного доступу; кнопка «Заповнити з гаманця» у формі посвідчення.

**Основний шлях**

1. Продукт показує доступні способи за країною: EUDI Wallet для країн ЄС, Дія.Шеринг для України, цифрові посвідчення водія через Digital Credentials API.
2. Екран показує атрибути, які буде запитано (ім'я, прізвище, дата народження), і мету запиту.
3. У вебі перевірка йде через Digital Credentials API браузера або через QR-код, який користувач сканує гаманцем на телефоні.
4. Продукт перевіряє підпис і статус атестації і зіставляє атрибути з профілем.
5. Зберігаються лише квитанція перевірки (джерело, дата, результат) і потрібні атрибути; credential не зберігається.
6. «Заповнити з гаманця» заповнює поля «Ім'я», «Дата народження», «Номер», «Строк дії» з позначкою «Перевірено · <дата>».

**Гілки та помилки**

- Дані не збігаються — «Дані гаманця не збігаються з профілем» і кнопка «Інший спосіб».
- Гаманець недоступний у країні — альтернатива: ключ відновлення, довірений пристрій або скидання Сейфу; ручної перевірки підтримкою немає.
- Гаманець передав не всі атрибути — повідомлення, наприклад «Гаманець не передав номер документа».
- Ручна зміна поля знімає позначку «Перевірено» лише з цього поля.
- Продукт не стає гаманцем і не зберігає ідентифікаційні дані особи понад потрібні атрибути.

**Екрани і стани:** Вибір гаманця · Запит атрибутів · QR-код · Результат перевірки (успіх, не збігається, недоступно) · Поля з позначкою «Перевірено».

**Метрика успіху.** Не менше 90 % перевірок успішні з першої спроби; 0 збережених credential.

**Критерії приймання**

1. **Given** користувач в Україні **When** відкривається «Підтвердіть особу» **Then** серед способів є Дія.Шеринг.
2. **Given** атрибути збігаються з профілем **When** перевірка завершена **Then** збережено квитанцію з джерелом, датою і результатом, без credential.
3. **Given** дата народження в гаманці відрізняється від профілю **When** перевірка завершена **Then** показано «Дані гаманця не збігаються з профілем» і «Інший спосіб».
4. **Given** форма посвідчення **When** користувач натискає «Заповнити з гаманця» і підтверджує **Then** поля заповнено з позначкою «Перевірено · <дата>».
5. **Given** поле «Номер» з позначкою «Перевірено» **When** користувач змінює його вручну **Then** позначка знята лише з цього поля.
6. **Given** браузер без підтримки Digital Credentials API **When** користувач починає перевірку **Then** показано QR-код для гаманця на телефоні.

**Граничні випадки**

- Поля не оновлюються автоматично — лише новою перевіркою.
