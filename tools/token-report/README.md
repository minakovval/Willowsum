## Рядок «Сесії» (огляд процесу 15, пропозиція 4; власник, 2026-11-16)

- **Знімок** — результат `get_session` (без `session_id`), збережений у JSON-файл на старті сегмента і наприкінці
  (`keep/snap-<N>-start.json`, `keep/snap-<N>-end.json` у scratchpad). Скрипт читає `ccr.external_metadata.usage`
  (`cache_read_tokens`, `output_tokens`, `cost_usd`) і час `ccr.updated_at`. Підходить і коротка форма
  `{ "at": "<ISO>", "usage": { "cache_read_tokens": …, "output_tokens": …, "cost_usd": … } }`: поле `at` має
  перевагу. Короткою формою відновлюють знімок, якщо файл утрачено, — з коментаря-знімка на #180.
  Немає `usage` (на старті сесії поле може бути відсутнім) — скрипт відмовляє (exit 1): зробіть знімок ще раз.
- **Колонки.** Три колонки cache read (власник, 2026-11-28, огляд токенів, A2): **разом** — різниця знімків (з агентами),
  **агенти** — сума «Агенти: cache read, млн» рядків PR із `--prs`, **сам ведучий** — cache read власного журналу ведучого
  у вікні знімків (`--lead <transcript.jsonl>`, ті самі суми, що в `session`; без `--lead` — «—»). Output і ≈ USD — різниця
  знімків. Заголовок таблиці «Сесії» у тілі #180 має бути таким: `| Сесія | Період | cache read, разом | cache read, агенти |
  cache read, сам ведучий | output | ≈ USD | Тривалість, год | Час агентів, год | CI, год | Примітка |`. Тривалість —
  час між знімками. «Час агентів» — сума «Час автора» і «Час рецензій» рядків PR із `--prs`, CI — сума їхніх «CI»
  (хвилини → години). Примітка — «N PR (#a, #b)» і `--note`.
- **Відмови (exit 1, файл не змінюється):** PR із `--prs` без рядка в таблиці «PR» (спершу `pr` і `append`), не
  число в його колонках часу чи CI, кінцевий знімок не пізніший за стартовий, використання між знімками
  зменшилося (знімки з різних сесій). Рядок «Сесії», переданий через `--row`, не може мати порожніх «Час
  агентів» чи CI.
- **Примітка** — до 250 символів у «Сесіях», до 120 у «PR».

## Журнал агентів і `batch` (власник, 2026-11-27, п. 5 огляду рішень)

- **Журнал** — TSV, один рядок на кожен запуск агента, ведучий дописує його на старті агента:
  `PR<TAB>роль<TAB>модель<TAB>agentId[<TAB>причина]`, напр. `#612<TAB>a<TAB>S<TAB>a1b2c3`. Необов'язкова 5-та колонка —
  причина другого кола: `тест`, `правило`, `безпека` або `інше` (на рядку `f`/`c`); порожня чи відсутня — у примітці
  нічого не пишеться. Роль: `a` автор, `r` рецензія, `s` безпека,
  `f` виправлення, `c` підтвердження; модель — код для примітки (S, O, F). Рядки порожні або з «# » на початку
  пропускаються. Відновлений агент — той самий або новий рядок з тим самим `agentId`.
- **Рядок «PR».** Витрати — `usage` кожного виклику з `<tasks>/<agentId>.output`, кожен `message.id` один раз, по
  `message.model`. Колонки (власник, 2026-11-28, огляд токенів, пропозиція 0): `PR | Тип | Раунди | Агенти: cache read,
  млн | Агенти: cache write, млн | Агенти: input, тис. | Агенти: output, тис. | Час автора, хв | Час рецензій, хв | CI, хв |
  Примітка`. `subagent_tokens` (останній контекст запуску) прибрано: `--run …,tokens=` ще приймається й ігнорується.
  Тривалість запуску — від першого до останнього `timestamp` журналу; роль `a`, `f` → «Час автора»,
  `r`, `s`, `c` → «Час рецензій». CI — як у `pr` (`--branches "#12=гілка"`; PR без гілки — помилка). Тип — `код`, якщо
  не задано `--types`. «Раунди» — 2, коли в журналі є рядок `f` чи `c`, інакше 1 (число рядків `r` не рахується).
  Примітка — `a:S r:O f:S r2: тест` (причина з 5-ї колонки журналу) + «журнал втрачено: …» + «моделі: …» (ліміт 120).
  Підтримані примітки, які читає дашборд, не змінено: «моделі: opus X млн / sonnet Y / fable Z» і «Сам ведучий … — N млн»
  (це `--note`, ведучий пише його сам).
- **Міграція #180.** Обидва заголовки в тілі оновлюють **до наступного запуску `batch`** (рядок не додається, якщо кількість
  клітинок не збігається із заголовком). «PR» (11 колонок): замініть колонку «Токени агентів (`subagent_tokens`)» на
  «Агенти: cache write, млн» і «Агенти: input, тис.» (після «Агенти: cache read, млн»). «Сесії» (11 колонок):
  `| Сесія | Період | cache read, разом | cache read, агенти | cache read, сам ведучий | output | ≈ USD | Тривалість, год |
  Час агентів, год | CI, год | Примітка |`. Старі рядки під зміненим заголовком не вирівнюються: `sessionRow` читає клітинки
  рядків «PR» за назвами колонок, тож старий рядок із `--prs` дає помилку «not a number» (exit 1, файл не змінюється) —
  це навмисно; виправте або перепишіть такий рядок вручну.
- **Журнал не знайдено** — рядок усе одно пишеться з тим, що є, з приміткою «журнал втрачено» і попередженням у stderr.
- **PR із рядком** у «PR» пропускається (друкується «skipped»). Помилка (PR не в журналі, CI = 0 для `код`/`UI`/
  `виправлення`, погані знімки) — exit 1, файл не змінюється.
- **«Сесії»** — як у `append --sessions`, з `--prs` або всіма PR журналу.
- Після запуску: `gh api -X PATCH repos/{owner}/{repo}/issues/180 -F body=@<файл>`.
