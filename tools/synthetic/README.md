# tools/synthetic — синтетичні дані

**Створено:** 2026-11-06 · **Оновлено:** 2026-11-17

Детермінований генератор синтетичних просторів і їхніх даних для тестів і staging (ARC-03 п. 6, П-9).
Лише вигадані дані: агенти й тести ніколи не використовують реальні.

## Як працює

- Простори: «Synthetic household N», регіон «eu», власне посилання на ключ `synthetic-key-NNNN`
  (заглушка, не ключ). Таблиці просторів поки немає (ACC-08).
- Кожен модуль реєструє генератор своїх таблиць у `apps/api/src/modules/<module>/synthetic.ts`:
  `export const synthetic = [defineSyntheticTable({ table: "<схема>.<таблиця>", perHousehold, rows })]`.
  `perHousehold` — обсяг для тестів і staging; вимога — 10 000 активів і 100 000 транзакцій на простір
  (генератори додадуть модулі `asset-registry` і `transactions`).
- Псевдовипадкові числа — sfc32 із зерном-рядком (не криптографія); зерно окреме для кожної пари
  «простір + таблиця», тож нова таблиця не змінює дані інших. Суми будуються цифрами як рядки, без float.
- Рядки йдуть потоком, у пам'яті — один рядок.

## Команда

```
node tools/synthetic/index.ts --out <dir> [--seed willowsum] [--households 1] [--format csv|sql] \
  [--count <схема.таблиця>=<рядків на простір>]
```

`csv` — файл `<схема.таблиця>.csv` на таблицю; `sql` — `synthetic.sql` з блоками `COPY … FROM stdin` для
завантаження власником схем через psql у тестову базу.

Тести: `pnpm --filter @willowsum/synthetic test` (детермінізм, обсяг 10 000 + 100 000, формати);
тест ізоляції `apps/api/test/isolation.it.test.ts` заповнює кожну таблицю клієнтів цими генераторами.

## Виписки родини (ARC-03 п. 6)

Вигадана родина в масштабі 2–3 років: 4 банки (monobank, Revolut, BBVA, Raiffeisen Україна), 7 рахунків у UAH, EUR
і USD, кредитна картка з лімітом і щомісячним погашенням, автокредит із відсотками і внесками, перекази між
власними рахунками (зокрема обмін EUR → USD), покупки за кордоном у EUR з курсом, скасовані (REVERTED) платежі.
Для регресії шаблонів імпорту (IMP-06, IMP-10) і наскрізних сценаріїв.

```
node tools/synthetic/family.ts --out <dir> [--seed willowsum] [--start 2024-01-01] [--years 2|3]
```

- Файли: `<банк>/<рахунок>-<рік>.csv|xlsx`, один на рахунок і календарний рік. monobank — CSV UTF-8 з BOM, усі поля
  в лапках, нові рядки зверху; Revolut — CSV UTF-8, файл на валюту; BBVA — XLSX зі шапкою, клітинками дат і чисел
  (рахунок і кредит); Raiffeisen — CSV Windows-1251 без BOM, «;», CRLF, шапка, «Дебет» / «Кредит», «1 234,56»,
  підсумкові рядки. Макети наближені до банківських і звіряються з шаблонами бібліотеки (IMP-10).
- `truth.json` — що імпорт має прочитати: рахунки (вхідний і вихідний залишки), транзакції (дата, сума зі знаком,
  валюта, залишок після), перекази (обидві ноги, курс обміну), для кожного файлу — кодування, роздільник, рядок
  заголовка, порядок, залишки періоду і відповідність «рядок → транзакція» або пропуск («reverted», «summary»).
- Детермінізм: той самий `--seed` дає ті самі байти; потік кожного рахунку і місяця має власне зерно.
- Лише вигадані дані: власники «Synthetic Parent A/B», IBAN із контрольними цифрами «00» (недійсні), картки
  `0000 00** **** NNNN`. Суми — `Decimal`, не float.

Тести: `tools/synthetic/src/family.test.ts` — читає кожен файл незалежним читачем і звіряє з `truth.json`.
Генератора активів у PoC немає (PoC v2).
