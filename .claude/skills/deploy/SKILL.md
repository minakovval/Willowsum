## 1. Prerequisites

1. The owner's OCI account is ready: the owner wrote «акаунт OCI готовий» after `infra/start/owner-setup.md`
   (Pay As You Go, home region Madrid, Frankfurt subscribed, MFA, 5 EUR budget alarm). If not, stop and tell the
   owner; do not create or touch the account.
2. The bootstrap of `infra/start/README.md` is done by the owner: state bucket `willowsum-tofu-state`, the
   state passphrase in the secrets store, the OIDC trust between GitHub and the cloud for `main` (CICD-12).
   Without it there is no plan/apply pipeline. **Перевірити, коли буде сервер:** how the pipeline runs
   `tofu plan` / `apply` (not in the repo yet).
3. The change is merged to `main` with CI green: deployment is for an image from `main` that passed all checks
   (CICD-05@PoC FR1).

## 2. Secrets

1. Production secrets live only in OCI Vault and the owner's password manager (CICD-12, `docs/ops/integrations.md`).
   Never in chat, an issue, a PR, a file, a log or the repository.
2. A missing key (e.g. the Resend key, the Turnstile secret) → ask for it through the secure credential form,
   never by chat. Name the variable and where it goes; never ask the owner to paste it.
3. **No production GitHub token on the server** (CICD-12; integrations list). CI reads only its own project of
   the secrets store; the pipeline reaches the cloud through OIDC from `main`, with no stored keys.
4. Internal secrets (database passwords, signing keys) are generated by the infrastructure code, not by hand
   (CICD-12 FR2). The master key never leaves the KMS.

## 3. Owner approval

Applying infrastructure (`tofu apply`), deploying to production and changing the workflows that do this, the
trust settings (OIDC, production secrets store) or production DNS need the owner's approval (AGENTS.md
step 7; ADR-0008). It is **either**:

- a comment from the owner's own GitHub account with a line that is exactly «Схвалюю» or «Approved»; **or**
- the owner's decision from chat recorded in the PR body as a line `Рішення власника (YYYY-MM-DD): схвалено …`.

**Agents never write a «Схвалюю» or «Approved» line.** Write the body line only for a decision the owner
actually gave, and only after they gave it. If the owner commented «stop» or asked a question, do not merge or
deploy until they answer. Do not ask the owner to confirm a merge once the conditions hold.

## 9. Never

- Pay, change a plan, accept legal terms (ToS, DPA) or create or upgrade an account: those are the owner's.
- Touch resources of the wealth platform or of any other project (the shared domain's other records, other
  tenancies' resources).
- Put a secret anywhere but OCI Vault / the owner's password manager; paste one in chat, a PR or the repo.
- Apply infrastructure or deploy before the approval of section 3.
