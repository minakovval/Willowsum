# Deploy to Oracle Cloud (OCI)

**Створено:** 2026-11-12 · **Оновлено:** 2026-11-12

> **Not set up yet.** The server does not exist: `infra/start` is only validated in CI (no `tofu plan` or
> `apply` has run), and the plan/apply and deploy pipelines are not written. This skill states only what the
> repo already says. A step marked **«перевірити, коли буде сервер»** is a placeholder: do not invent its
> commands, paths or names; confirm it against the real server and the then-current docs, and update this
> skill in the same PR.

Sources: `infra/start/` (OpenTofu, `README.md`, `owner-setup.md`), CICD-04, CICD-05, CICD-07, CICD-08 and
CICD-12 in `docs/requirements/cicd/`, ADR-0008, `docs/ops/integrations.md`. App host: `willowsum.mina.yachts`
(owner, 2026-11-12). Only one environment exists in PoC: production; no staging (CICD-07@PoC).

## 1. Prerequisites

1. The owner's OCI account is ready: the owner wrote «акаунт OCI готовий» after `infra/start/owner-setup.md`
   (Pay As You Go, home region Madrid, Frankfurt subscribed, MFA, 5 EUR budget alarm). If not, stop and tell the
   owner; do not create or touch the account.
2. The bootstrap of `infra/start/README.md` is done by the owner: state bucket `willowsum-tofu-state`, the
   state passphrase in the secrets store, the OIDC trust between GitHub and the cloud for `main` (CICD-12).
   Without it there is no plan/apply pipeline. **Перевірити, коли буде сервер:** how the pipeline runs
   `tofu plan` / `apply` (not in the repo yet).
3. The change is merged to `main` with CI green: deployment is for an image from `main` that passed all checks
   (CICD-05@PoC FR1).

## 2. Secrets

1. Production secrets live only in OCI Vault and the owner's password manager (CICD-12, `docs/ops/integrations.md`).
   Never in chat, an issue, a PR, a file, a log or the repository.
2. A missing key (e.g. the Resend key, the Turnstile secret) → ask for it through the secure credential form,
   never by chat. Name the variable and where it goes; never ask the owner to paste it.
3. **No production GitHub token on the server** (CICD-12; integrations list). CI reads only its own project of
   the secrets store; the pipeline reaches the cloud through OIDC from `main`, with no stored keys.
4. Internal secrets (database passwords, signing keys) are generated by the infrastructure code, not by hand
   (CICD-12 FR2). The master key never leaves the KMS.

## 3. Owner approval

Applying infrastructure (`tofu apply`), deploying to production and changing the workflows that do this, the
trust settings (OIDC, production secrets store) or production DNS need the owner's approval (AGENTS.md
step 7; ADR-0008). It is **either**:

- a comment from the owner's own GitHub account with a line that is exactly «Схвалюю» or «Approved»; **or**
- the owner's decision from chat recorded in the PR body as a line `Рішення власника (YYYY-MM-DD): схвалено …`.

**Agents never write a «Схвалюю» or «Approved» line.** Write the body line only for a decision the owner
actually gave, and only after they gave it. If the owner commented «stop» or asked a question, do not merge or
deploy until they answer. Do not ask the owner to confirm a merge once the conditions hold.

## 4. Build

The production web build is `pnpm --filter @willowsum/web build:production` (mode `production`). It needs
`VITE_CAPTCHA_SITE_KEY` (the public Cloudflare Turnstile site key) and fails without a well-formed key;
`pnpm build` (mode `ci`) is for local and CI only (`apps/web/README.md`). **Перевірити, коли буде сервер:**
the API image build, the registry and how the image reaches the server (CICD-05 FR1 requires an image from
`main` with all checks green; nothing is written yet).

## 5. DNS

The record for `willowsum.mina.yachts` is in the `mina.yachts` zone at Spaceship, the owner's account (shared
with another project). The agent never changes DNS: write a browser task for the owner's local session
(`browser-task` skill, `docs/ops/browser-tasks/NN-<topic>.md`), update `docs/ops/integrations.md` in the same
PR, and note that production DNS changes need approval (section 3). Do not touch other records of the zone.
The server's public address comes from the infrastructure outputs after the owner-approved apply;
**перевірити, коли буде сервер:** the record type and value, and whether a CDN stands in front (`infra/start`
lists it as not done).

## 6. Deploy

CICD-05@PoC describes the intended flow: a manual start by the owner, confirmed with the first 7 characters of
the commit hash; a DB restore point first; migrations as a separate step before the code; the new version
beside the old one, traffic switched after «ready»; smoke tests (sign-in, a record in a test space, a
background job); automatic return to the previous version on failure; a release log entry (version, time,
who approved, PRs). **Перевірити, коли буде сервер:** the actual workflow and commands do not exist yet; do
not run or invent them. Agents act in production only through the allowlisted pipeline actions after owner
approval (CICD-08 FR3) and never read the production database, secrets or server shell.

## 7. Post-deploy check

PoC has no Grafana, no staging and no external alive-check (owner, 2026-11-12; CICD-07@PoC FR4–5): open the
app at `https://willowsum.mina.yachts` and look at the structured logs (one JSON line per record on standard
output, `WS_TELEMETRY=off`; kept 30 days, only the owner can read them). The owner learns of a failure by
opening the app. An agent reads nothing in production; it uses lines the owner passes it, if they contain no
personal data. **Перевірити, коли буде сервер:** where to open the logs on the host.

## 8. Rollback

Code rolls back to the previous version without rolling back the schema (migrations stay compatible with the
previous code, CICD-05 FR5); target ≤ 5 min. Rolling back is an allowlisted action run by the pipeline after
owner approval (CICD-08 FR3), never by hand on the server. **Перевірити, коли буде сервер:** the command or
workflow. The DB restore point and the off-site copies (Frankfurt) are for data loss, not for a code rollback.

## 9. Never

- Pay, change a plan, accept legal terms (ToS, DPA) or create or upgrade an account: those are the owner's.
- Touch resources of the wealth platform or of any other project (the shared domain's other records, other
  tenancies' resources).
- Put a secret anywhere but OCI Vault / the owner's password manager; paste one in chat, a PR or the repo.
- Apply infrastructure or deploy before the approval of section 3.
